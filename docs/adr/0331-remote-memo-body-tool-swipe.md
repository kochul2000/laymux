# 0331. Remote 메모 본문은 수평 도구 스와이프를 받는다

- Status: Proposed
- Date: 2026-10-16
- Source: 사용자 요구("메모플링만 해결하고 말아라", "깃헙은 그대로 둬"), [ADR-0261](0261-remote-visible-tool-swipe-cycle.md), [ADR-0263](0263-remote-tool-swipe-hint-removal.md), [api-contracts.md §13](../architecture/api-contracts.md)
- Partially supersedes: ADR-0261의 textarea 제외 규칙 중 Remote 메모 본문에 한정한다.

## Context

Remote 메모는 본문 대부분을 textarea가 차지한다. 기존 도구 스와이프는 입력칸을 제외하므로 본문에서 가로로 플링해도 다음 도구로 이동하지 않는다. 본문을 자연스러운 제스처 시작점으로 제공하면서 입력·선택·세로 스크롤과 저장하지 않은 초안을 보존해야 한다. GitHub·Files 동작, 순환 순서와 기기 설정은 이번 결정의 범위 밖이다.

## Decision

**Remote 메모 본문만 기존 단일 도구 스와이프 소유자의 입력칸 제외 규칙에서 예외로 허용한다.**

- 터치·펜의 수평 이동은 기존 56px·수직 대비 1.25배 임계값과 pointerup 한 단계 실행 규칙을 따른다. 왼쪽은 다음 도구, 오른쪽은 기존 기기 설정의 닫기 또는 이전 도구다.
- 본문 자체의 `touch-action: pan-y`로 브라우저에 세로 스크롤을 맡기고 수평 pointer를 유지한다. 세로 우세 이동·취소·다중 포인터는 기존 취소 규칙을 따른다.
- 문서 선택 또는 포커스된 메모 입력칸의 선택 범위가 있으면 전환하지 않는다. 탭·마우스 편집과 다른 입력칸의 제스처 제외를 유지한다.
- 초안·저장 상태는 기존 MemoDocument가 소유한다. 플링은 기존 도구 이동만 호출하며 저장·폐기하지 않는다. 새 설정·호스트 API·권한·영속 상태는 추가하지 않는다.

## Alternatives Considered

- 헤더에서만 플링 허용: 화면 대부분인 본문에서 전환할 수 없다는 문제를 해결하지 못한다.
- 모든 입력칸에 적용: 다른 편집 표면까지 제스처 책임이 확장되고 선택·가로 스크롤과 충돌한다.
- 모든 touchmove 차단: 메모의 자연스러운 세로 스크롤을 훼손한다.

## Consequences

- 본문에서 기존 도구 이동을 사용할 수 있고 저장 전 초안도 유지된다.
- 메모 본문의 수평 터치 팬은 도구 이동이 소유한다. 선택 범위가 있으면 선택 해제 후 플링해야 한다.
- 실제 Chromium 터치 입력으로 좌우 플링·세로 스크롤·선택 보호·초안 보존을 검증하고 생성 번들의 원본 일치를 검사한다. 다른 편집기에도 확장하려면 별도 결정을 거친다.
