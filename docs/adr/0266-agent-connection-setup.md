# 0266. 에이전트 연결 설정은 선택한 프로필에서 검사하고 명시적으로 새 pane을 연다

- Status: Proposed
- Date: 2026-09-25
- Source: 사용자 요구(연결 설정 세 항목 중 에이전트 연결만 우선 구현), [issue #1076](https://github.com/kochul2000/laymux/issues/1076), [연결 설정 계획](../walkthrough-implementation-plan.md), [api-contracts.md §10](../architecture/api-contracts.md#10-settings)
- Extends: [ADR-0125](0125-configurable-agent-launch-command.md)의 설정 소유 명령을 명시적인 신규 실행에도 적용한다. 기존 복원 명령 검증은 유지한다.

## Context

개발자가 에이전트의 설치 위치와 실행 환경, 로그인 절차, laymux의 실행 명령 설정을 각각 찾아야 한다. Windows에 설치된 CLI가 WSL에서도 준비됐다고 표시하거나 PTY 생성 성공을 로그인 성공으로 표시하면 설정을 끝냈다는 잘못된 인상을 준다.

사용자는 강제 시작 마법사와 실습을 원하지 않으며, 에이전트·MCP·휴대폰의 선택형 연결 설정 중 에이전트 항목을 먼저 구현하도록 지정했다. 기존 사용자 명령·프로필·작업 pane을 보존하면서 준비 상태 확인과 실제 실행을 한 화면에서 제공해야 한다.

ADR-0125의 명령 설정은 세션 복원용이며, 현재 터미널 생성의 문자열 override는 복원 등 제한된 형태만 허용한다. 신규 실행을 위해 임의 문자열을 허용하거나 설정을 임시로 덮어쓰면 책임 경계가 달라진다. 설치 안내용 셸도 프로필의 기존 startupCommand가 자동 실행되면 사용할 수 없으므로 일회성 시작 의도가 필요하다.

범위는 Claude Code·Codex·Grok의 선택형 연결 설정, 프로필별 설치 진단, 명시적인 새 pane 실행이다. MCP 등록·휴대폰 연결·인증정보 수집·자동 설치·학습 진행 저장은 포함하지 않는다.

## Decision

**에이전트 명령과 실행 환경은 기존 설정이 소유하고, 연결 페이지는 해당 환경의 제한된 설치 검사와 구조화된 일회성 시작 요청만 수행한다.**

- 연결 페이지는 기존 Settings 컨테이너의 `agentSetup` 섹션이다. 상단 `연결 설정` 및 설정 내비게이션에서 선택적으로 열며 앱 시작 시 자동으로 열지 않는다. 기존 `ui.navigateSettings`로도 같은 섹션에 진입한다.
- `check_agent_installation(agentId, profileName)`는 저장된 에이전트 명령과 정확한 프로필을 Rust에서 해석한다. 프론트가 임의 검사 명령이나 환경을 보내지 않는다. 설정의 명령 정규화는 기존 ADR-0125와 같은 규칙을 사용한다.
- 진단은 해당 환경의 실행 파일 조회와 고정 `--version` 실행으로 제한한다. 사용자 지정 에이전트 플래그는 검사에 넣지 않는다. 선택한 프로필의 지원되는 셸과 초기화 옵션, 상속 환경, WSL 배포판/사용자를 사용한다. 별도의 프로필 환경 변수 설정을 도입하지 않으며, 해석할 수 없는 실행 환경을 다른 환경으로 대체하지 않는다.
- 자동 검사와 명시적인 에이전트 시작은 기존 PTY의 시작 명령 지원이 있는 Windows PowerShell·WSL 프로필로 제한한다. CMD·네이티브 Linux Bash 등 시작 명령을 실행하지 않는 셸에는 `unknown`과 공식 문서·수동 터미널 경로를 제공하고, 구조화된 에이전트 시작 요청은 오류로 거부한다. 이 기능 때문에 일반 PTY의 셸 초기화 정책을 확장하지 않는다.
- 프로브는 `headless_command()`와 제한된 실행 시간·출력으로 수행한다. 확인된 부재는 `missing`, 실행 가능한 설치 확인은 `installed`, 지원하지 않는 환경·시간 초과·모호한 실패는 `unknown`으로 구분한다. 결과는 현재 요청의 agent/profile/config에만 유효하며 대상 변경 후 도착한 응답은 표시하지 않는다.
- 설치 상태와 로그인 상태를 분리한다. laymux는 자격 증명을 읽거나 복사하지 않는다. 설치 검사가 통과해도 인증 완료를 표시하지 않으며 공식 로그인 안내를 제공한다. PTY 준비 상태 역시 프로세스의 인증·작업 성공을 보증하지 않는다.
- 설치·로그인 안내는 공식 문서 링크와 해당 환경에 맞는 명령 복사를 제공한다. 페이지 로드나 검사만으로 설치 스크립트·로그인·유료 요청을 실행하지 않는다. 명령 편집은 기존 에이전트 설정을 재사용한다.
- 에이전트 실행 클릭은 기존 작업을 보존하는 새 pane과 일회성 `agentStartup: { agentId }` 요청을 만든다. Rust는 저장된 명령을 다시 도출해 이 생성의 프로필 startupCommand를 대체한다. 호출자는 임의 명령·플래그를 실어 보낼 수 없다.
- 설치·로그인을 위한 터미널 열기는 일회성 `shellOnlyStartup: true`로 이 생성의 프로필 startupCommand만 생략한다. 셸·프로필 환경·CWD 정책은 유지한다. 두 요청은 서로 및 기존 viewer/문자열 startup override와 상호 배타적이다.
- 시작 의도는 UI runtime에서만 보유한다. settings.json·workspace/layout 내보내기·세션 snapshot에 저장하지 않으며, 터미널 생성/정리 수명에 맞춰 제거한다. 일반 터미널 생성과 다음 재기동의 기존 세션 복원 정책은 유지한다.
- 별도의 완료 이력·진행률 저장을 만들지 않는다. 사용자가 다시 방문하면 현재 설정과 진단 결과를 사용한다. 페이지 선택은 에이전트의 전역 기본값이나 사용량 수집 프로필을 바꾸지 않는다.

## Alternatives Considered

- **설명과 외부 문서 링크만 제공한다.** 가장 작지만 설치 환경 불일치와 현재 실행 명령을 확인하기 어렵고 새 사용자에게 설정 화면을 다시 탐색하게 한다.
- **사용량 프로브 성공을 로그인 완료로 사용한다.** 별도의 사용량 프로필·계정 경로와 선택한 실행 프로필이 다를 수 있고, 조회 비용·실패 원인도 달라 연결 상태의 근거로 사용하지 않는다.
- **startup 문자열 override를 일반 명령으로 확장한다.** 기존 Rust 검증의 의미가 바뀐다. 서버가 명령을 도출하는 구조화 요청을 사용한다.
- **프로필 startupCommand를 일시 수정하고 복구한다.** 다른 pane 생성과 설정 저장에 영향을 주고 복구 경합이 생긴다. 일회성 생성 요청으로 한정한다.
- **기존 작업 pane에 설치·실행 명령을 보낸다.** 셸인지 실행 중인 프로그램인지에 따라 작업을 훼손할 수 있다. 명시적으로 새 pane을 만든다.
- **학습용 workspace와 단계 완료 이력을 도입한다.** 사용자가 설정형 안내로 범위를 좁혔으므로 필요하지 않다.

## Consequences

개발자는 같은 페이지에서 에이전트와 실행 프로필을 고르고 설치·로그인 안내·실행으로 이어갈 수 있다. 기존 설정을 재사용하며 다른 pane의 입력이나 시작 동작을 바꾸지 않는다.

셸 및 WSL 환경 검사에는 지원 범위와 실행 시간 제한이 생긴다. 사용자별 셸 함수·원격 접속 래퍼처럼 확정할 수 없는 구성은 `unknown`으로 표시하고 해당 환경의 터미널에서 확인하게 한다. CMD·네이티브 Linux Bash의 자동 실행을 지원하려면 기존 PTY의 시작 명령 정책과 수명을 먼저 검토해야 한다. 공식 설치 안내는 공급자 변경에 맞춰 유지해야 한다.

IPC와 일회성 시작 의도가 추가되므로 잘못된 agent/profile, 상호배타 입력, timeout, 설정 변경 중 응답, 생성 실패와 cleanup, snapshot 비영속을 검증한다. 새 설정 스키마나 마이그레이션은 없다. 기존 설치·로그인·프로필을 보존하는 dev 화면 및 실제 실행을 확인하고 관련 living doc을 같은 PR에서 동기화한다.
