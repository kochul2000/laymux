# 0237. Remote 플로팅 입력은 기기 로컬 배치와 기존 액션을 공유한다

- Status: Proposed
- Date: 2026-09-07
- Source: 사용자 요구(방향키 2종·임의 개수 탭 버튼·상단바 액션), [api-contracts.md §13.4](../architecture/api-contracts.md#134-terminal-control)
- 관계: ADR-0213의 행 배치 모델과 ADR-0228의 방향키 반복 정책을 확장한다.

## Context

하단 입력 행만으로는 엄지에 가까운 임의 위치에 버튼을 둘 수 없다. 커서 방향키와 패널·알림 탐색 패드는 플릭을 사용하므로 이동 드래그와 구분해야 한다. 메뉴·복사·파일 탐색·스킵·PC 모드도 입력 행과 플로팅에서 선택할 수 있어야 한다. 호스트 설정과 Remote 전송 계약은 범위 밖이다.

## Decision

**기기 로컬 keybar 설정에 플로팅 배치를 추가하고 모든 실행은 기존 액션에 위임한다.**

- `laymux.remote.keybar.floating`이 두 패드의 활성 여부와 크기·위치 및 일반 버튼 인스턴스 목록을 소유한다. 기본은 모두 꺼짐/빈 목록이다. 행 배치는 유지하고 동일 액션의 여러 플로팅 인스턴스를 허용한다.
- 위치는 가용 화면 안의 정규화 좌표(0–1), 크기는 44–128 CSS px다. 화면 회전·키보드 표시로 가용 영역이 바뀌면 현재 영역 안에 재배치하며 저장 위치를 덮어쓰지 않는다.
- 일반 버튼은 탭 한 번에 기존 액션을 한 번만 실행한다. 방향키 단일 버튼도 길게 누르기 반복 없이 탭만 받는다. 이동 임계값을 넘는 드래그와 취소는 액션을 실행하지 않는다.
- `Keys`가 행에서 숨겨져 있어도 활성 플로팅 `Keys`가 있으면 확장행을 열 수 있다. 마지막 토글을 숨기면 확장행도 닫는다.
- 두 패드는 기존 플릭 및 커서 패드 반복을 유지한다. 별도 이동 손잡이가 사용 화면에서 드래그를 받고 설정의 X/Y 입력은 드래그 없는 위치 변경 경로다.
- 상단바 액션은 Hidden 목록에서 기본 미배치 상태로 제공한다. 복제 버튼은 원본의 실행·활성 조건·토글 상태를 공유하며 원본을 옮기거나 독립 전송 경로를 만들지 않는다.
- 저장값은 알려진 액션·고유 인스턴스 ID·유한 수치인지 검증하고 잘못된 항목은 버린다. 패드는 일반 탭 버튼 피커에서 제외한다. 사용자 키 삭제 시 해당 플로팅 인스턴스도 제거한다.
- 기존 lease/권한 검증을 재사용한다. 새 Remote·Automation API는 필요하지 않으며 브라우저 테스트가 실제 DOM 설정·드래그·탭을 조작한다.

## Alternatives Considered

- 사용 화면 전체에 편집 모드를 추가: 이동할 때마다 별도 모드 진입을 요구하므로 직접 이동 요구에 맞지 않는다.
- 패드 자체 드래그로 이동: 방향 플릭과 같은 제스처라 입력 오작동 위험이 있다. 이동 손잡이로 분리한다.
- 호스트 설정에 위치 저장: 기기별 화면 크기·엄지 위치가 달라 기존 기기 로컬 소유권을 유지한다.

## Consequences

사용자는 같은 액션을 여러 위치에 놓을 수 있으며 상단바 액션도 재사용한다. 브라우저 저장소를 지우면 배치가 사라진다. 겹침은 사용자 배치로 허용하며 자동 정렬·서버 동기화는 제공하지 않는다. 정규화·중복 액션·드래그 취소·화면 크기·실행 횟수는 브라우저 테스트로 검증한다. iOS 실제 키보드/포인터 동작은 실기기 재검증 대상이다.
