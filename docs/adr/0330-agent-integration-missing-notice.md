# 0330. 실제 사용한 에이전트 환경의 훅·MCP 미설치를 앱 알림으로 안내한다

- Status: Accepted
- Date: 2026-10-15
- Source: 사용자 요구(훅·MCP 미설치 때도 갱신 알림처럼 자동 안내, 다시 보지 않기 포함), [ADR-0282](0282-optional-agent-hook-installation.md), [ADR-0289](0289-agent-hook-update-notification.md), [ADR-0324](0324-agent-hook-inspection-on-discovery.md), [ADR-0325](0325-agent-mcp-registration.md), architecture/api-contracts.md 에이전트 훅 관리
- 관계: ADR-0289의 앱 알림을 미설치 안내로 확장한다. ADR-0324의 자동 검사 발견 근거에 휴리스틱 사용 관찰을, ADR-0325의 MCP 자동 검사 시점에 새 사용 대상을 추가한다(확장). ADR-0282의 선택 설치(자동 설치 금지)와 두 ADR의 앱 수명 검사 캐시·정지 WSL 미기동은 그대로 따른다.

## Context

갱신 알림(ADR-0289)은 이미 Laymux 소유 훅이 있는 대상만 판정한다. 훅이 전혀 없거나 MCP가 등록되지 않은 환경은 Settings를 열어야만 알 수 있다. 그래서 Claude·Codex를 쓰는 사용자가 작업 상태 훅이나 내장 MCP의 존재를 모른 채 지나간다.

반대로 검사한 모든 대상에 미설치를 알리면 쓰지 않는 CLI(예: Codex를 안 쓰는 사용자의 Codex, 실행 중인 모든 WSL 배포판)까지 알림이 뜬다. 훅은 선택 설치이므로(ADR-0282) 안내가 설치를 강요하거나 사용자가 방금 제거한 선택을 거슬러서도 안 된다.

훅 이벤트 관찰(`connections`)은 훅이 설치된 뒤에만 생기므로 미설치 판정의 사용 근거가 될 수 없다. 사용 근거는 훅과 독립된 기존 휴리스틱 감지(터미널 activity의 InteractiveApp)다. 이 감지는 provider만 알고 설정 폴더는 모른다. 터미널의 실행 환경은 Rust 세션의 최초 실행 호스트 분류와 셸이 보고한 WSL 배포판으로 알 수 있다.

범위: Claude·Codex의 훅과 MCP, 기본 설정 폴더의 미설치. 비목표: 자동 설치, 사용자 지정 설정 폴더 추측, Grok(훅 미지원이고 MCP는 Claude `.claude.json` 호환 읽기 때문에 기본 위치만으로 미설치를 판정할 수 없다), 주소가 다른 MCP 등록·주소 확인 불가 안내, SSH 원격 호스트, 원격 기기 알림.

## Decision

**휴리스틱 감지로 Claude·Codex 실행이 관찰된 로컬 실행 환경의 기본 설정 폴더에서 훅 또는 MCP가 미설치면 기존 갱신 알림 패널에 대상별 설치 동작과 함께 안내하고, 사용자는 settings.json 전역 토글로 이 안내를 끌 수 있다.**

- **사용 근거의 소유자는 Rust AppState다.** interactive app 감지가 Claude·Codex를 기록하는 지점에서 (터미널 ID, provider)를 앱 수명 메모리 레지스트리에 한 번 기록한다. 같은 터미널의 다른 provider는 별도 관찰이다. 기록 경로는 다른 AppState 락을 잡지 않는 leaf 락만 사용하고, 새 관찰의 검사 힌트는 감지 경로의 락 밖(별도 스레드)에서 묶어 발행한다. 닫힌 터미널의 관찰은 상한에서 빠지고 해석된 대상은 남는다.
- **실행 환경 해석은 안내 조회 때 한다.** 레지스트리 스냅샷을 복사하고 락을 놓은 뒤 터미널 세션을 읽으며, 레지스트리 락을 `terminals` 락·검사 gate·I/O와 겹쳐 보유하지 않는다. 셸이 보고한 WSL 배포판이 있으면 그 배포판, 없고 최초 실행 호스트가 native(Windows 또는 비Windows)면 native다. WSL 호스트인데 배포판을 아직 모르면 해석을 미루고, 배포판이 처음 설정될 때 검사 힌트를 발행해 다시 해석한다. SSH 직접 접속·분류 불명 호스트의 관찰은 대상에서 제외한다. 해석된 (provider, 배포판) 대상은 터미널이 닫혀도 앱 실행 동안 유지하고 재시작 때 비운다. 해석 전에 닫힌 터미널의 관찰은 버린다.
- **판정은 backend가 기존 앱 수명 캐시로만 한다.** 훅 미설치는 해당 대상 기본 폴더의 성공한 검사 결과에 Laymux 소유 훅과 helper가 모두 없고, 같은 provider·배포판의 다른 폴더에도 소유 훅이나 helper가 있는 성공 검사 결과가 캐시에 없는 경우다(관찰로 발견된 사용자 지정 폴더 설치를 존중한다). MCP 미설치는 기본 위치의 성공한 등록 검사가 "미등록"인 경우다. 검사하지 않았거나 실패한 대상은 미설치로 합성하지 않는다. 현재 실행에서 사용자가 명시적으로 제거한 대상(훅 또는 MCP, 기본 폴더)은 다시 설치하기 전까지 안내하지 않으며, 이 제외는 메모리에만 두고 재시작 때 비운다.
- **응답 계약.** `get_agent_hook_updates`와 `GET /api/v1/agent-hooks/updates` 응답에 `missing` 목록을 추가한다. 목록은 토글과 무관하게 같은 판정을 반환하고 토글은 표시에만 적용한다. REST 전체 재확인은 훅만 다시 검사하고 MCP는 캐시를 읽는다.
- **검사 시점.** 처음 해석된 사용 대상의 기본 폴더는 훅 자동 검사의 새 대상이다. 그 대상의 MCP 미검사 위치는 훅 안내를 지연시키지 않도록 별도 백그라운드에서 대상마다 한 번만 확인하고, 끝나면 기존 검사 힌트 이벤트로 안내 갱신을 요청한다. 훅·MCP 모두 WSL 대상은 실행 중으로 열거된 경우에만 확인하며 정지한 배포판을 시작하지 않는다. 토글이 꺼져 있으면 안내 전용인 MCP 백그라운드 확인을 요청하지 않는다. 프론트엔드는 이 힌트와 앱 시작에만 자동 검사를 요청한다. 실행 중 요청이 겹친 MCP 확인은 한 번 더 돌고, 시작 검사가 끝나면 힌트를 발행한다. 주기 검사는 추가하지 않는다.
- **알림은 기존 패널 하나다.** 대상별 줄에 "훅 미설치"·"MCP 미설치"를 표시하고 각각 설치 버튼을 둔다. 설치는 기존 관리 API(훅 install, MCP install)를 사용자가 누를 때만 실행한다. 알림과 Settings의 훅·MCP 관리는 같은 프론트엔드 큐에서 직렬화해 같은 설정 폴더 락(ADR-0325)의 즉시 실패를 앱 안에서 만들지 않는다. "나중에"는 ADR-0289처럼 현재 실행의 안내만 숨긴다.
- **다시 보지 않기는 settings.json의 `notifications.agentIntegrationMissing`(기본 true)이 정본이다.** 사용자 구성이므로 UI 로컬 상태가 아니라 설정 파일에 둔다. 알림의 "다시 보지 않기"를 체크하고 닫으면 이 값을 false로 저장한다. false면 미설치 줄만 숨기고 갱신 필요·검사 오류 안내는 계속 표시한다. Settings의 Claude·Codex 설정 화면에서 같은 값을 다시 켠다.
- 안내는 CLI 설정을 읽기만 한다. 자동 설치·자동 재설치, CLI 신뢰·전체 비활성 설정 변경, 사용자 지정 폴더 탐색을 하지 않는다.

## Alternatives Considered

- 검사한 모든 대상에 미설치 안내: 쓰지 않는 CLI와 모든 실행 중 WSL에 알림이 떠 선택 설치 원칙과 맞지 않는다.
- 훅 이벤트 관찰을 사용 근거로 사용: 미설치 상태에서는 이벤트가 오지 않아 판정 자체가 불가능하다.
- 훅 이벤트 관찰로 사용자 지정 폴더 설치를 판정: 관찰 레지스트리는 수 분 안의 이벤트만 반환해 안내가 다시 나타난다. 관찰로 발견돼 앱 수명 캐시에 남은 검사 결과를 쓴다.
- 프론트엔드가 터미널 프로필로 실행 환경을 추측: 배포판·호스트 분류는 Rust 세션이 가지고 있고, 단일 진실원이 둘이 된다.
- Grok MCP 포함: Claude 등록으로 이미 연결된 Grok을 미설치로 오탐한다.
- 다시 보지 않기를 localStorage 대상별 기록: 세밀하지만 사용자 구성이 브라우저 저장소에 흩어지고 복구 UI가 따로 필요하다.
- 별도 알림 패널 신설: 화면 점유가 늘고 갱신 알림과 설치 큐 직렬화가 분리된다.

## Consequences

Claude·Codex를 실제로 쓰는 로컬 환경에서 훅·MCP를 설정 화면 없이 발견하고 바로 설치할 수 있다. 기존 사용자에게도 기본으로 안내가 켜지므로 업데이트 직후 한 번 알림이 보일 수 있다.

위험: 사용 근거가 휴리스틱이라 감지되지 않은 실행(배포판 보고가 없는 WSL 세션)은 안내되지 않고, 출력에 배너 문자열이 섞인 경우 오탐할 수 있다. native 셸에서 `wsl`·`ssh`를 수동 실행하면 배포판 보고 유무에 따라 다른 환경으로 귀속될 수 있다. MCP는 사용자 범위만 보므로 project·local 범위 등록이나 셸 프로필의 설정 폴더 변수로 옮긴 등록은 미설치로 보일 수 있으며, 이때는 다시 보지 않기로 끈다.

비용: 설정 스키마·응답 필드 추가, 감지 기록 지점의 leaf 락과 레지스트리, MCP 백그라운드 확인, Settings MCP 관리의 큐 편입. 사용 관찰·환경 해석·판정·제거 제외·토글·알림 동작을 단위·컴포넌트 테스트로, 실제 알림 화면을 dev 스크린샷으로 검증한다. `state.rs` 락 순서 주석과 api-contracts 에이전트 훅 절을 갱신한다.

재검토 조건: 오탐 신고가 반복되거나, provider·대상별 다시 보지 않기 요구가 생기거나, CLI가 훅·MCP 설치를 자체 제공하게 되면 다시 판단한다. 호환되는 기능 추가이므로 버전 영향은 minor다.
