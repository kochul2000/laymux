# 0192. 액션 버튼은 공용 컴포넌트로 그리고, 비활성 컨트롤은 이유를 포인터 자리에서 말한다

## Context

Settings 의 업데이트 섹션에서 사용자가 "지금 확인"을 눌렀는데 아무 일도 일어나지 않았다. 원인은 로직 버그가 아니다 — 그 화면은 dev 빌드였고, `UpdateStatus::enabled` 는 `!cfg!(debug_assertions)` 이므로 false 였다(ADR-0190: debug 바이너리가 자신을 release 산출물로 덮어써서는 안 된다). 백엔드 게이트는 의도대로 동작했다.

문제는 그 게이트를 UI 가 전달하지 못한 방식이다. 그 버튼은 호출 지점마다 인라인으로 조립돼 있었다.

- `cursor: "pointer"` 가 `disabled` 여부와 무관하게 인라인 스타일에 박혀 있었다.
- `hover-bg` 클래스는 `:disabled` 를 구분하지 않아 비활성 버튼도 hover 하면 밝아졌다.
- 비활성 색·투명도 변화가 없었다.
- 이유("개발 빌드에서는 자기 갱신이 꺼져 있습니다")는 행 아래 별도 문단에만 있었다. 포인터가 있는 자리에는 아무 설명이 없었다.

그래서 정상 동작하는 안전장치가 **고장 난 기능**으로 관측됐다. 같은 조립 방식이 만든 두 번째 문제도 함께 신고됐다 — accent 색 글자 + 얇은 테두리로 만든 그 버튼들은 링크처럼 보여서 "정식 버튼"으로 읽히지 않고, 브라우저를 새로 여는 버튼과 앱 안에서 끝나는 버튼이 겉으로 구분되지 않았다.

강제하는 force 는 세 가지다.

1. **hover·disabled 는 CSS 의 일이다.** 인라인 스타일에는 `:hover`·`:disabled` 가 없으므로, 인라인으로 조립하는 방식은 비활성 상태를 표현할 방법 자체가 없다(§15 의 "호버는 CSS 클래스" 규칙이 이미 같은 이유를 말한다).
2. **비활성의 이유는 화면마다 다르다.** dev 빌드 게이트, 진행 중인 작업, 아직 도착하지 않은 상태 — 세 경우가 같은 버튼에서 발생한다. 하나의 문단으로는 어느 것인지 말할 수 없다.
3. **아이콘 자원이 없다.** 앱에는 아이콘 폰트·아이콘 패키지가 없고 모든 글리프가 손으로 그린 인라인 `<svg>` 다. "새 창에서 열기 기본 아이콘"을 넣으려면 그 자원을 어디서 가져오는지 정해야 한다.

범위는 사용자 액션 버튼의 공용 표현, 비활성 상태의 표시 의무, 앱을 떠나는 버튼의 표시, 그 아이콘의 출처다. 업데이트 로직·채널 정책·dev 게이트 자체는 비목표다(그 결정은 ADR-0190 이 소유하며 이 ADR 은 건드리지 않는다).

## Decision

**액션 버튼은 `components/ui/Button` 하나로 그리고, 변종·hover·`:disabled` 는 `index.css` 의 `.ui-btn*` 가 소유한다. 비활성 컨트롤은 비활성으로 보이는 동시에 그 이유를 포인터 자리(`title`)에서 말한다. 앱을 떠나는 버튼은 external-link 아이콘으로 그것을 미리 알린다.**

1. **버튼은 공용 컴포넌트에서 온다.** `Button` 은 `variant: "primary" | "secondary"` 와 `icon` 슬롯만 갖는다. `primary` 는 그 화면이 사용자에게 권하는 단 하나의 동작(채워진 accent 배경 + `--bg-base` 글자 — 이미 `.remote-control-reclaim-button` 이 쓰는 표현), `secondary` 는 나머지 전부다. 새 액션 버튼을 인라인 스타일로 조립하지 않는다.

2. **hover·active·disabled 는 CSS 클래스가 소유한다.** `.ui-btn` 에 클릭 피드백(`:active` 1px 눌림)을, `.ui-btn:disabled` 에 `opacity: 0.45` + `cursor: default` 를, 각 변종의 `:hover` 에 `:not(:disabled)` 를 붙인다. 비활성 버튼은 hover 해도 밝아지지 않는다. 인라인 스타일에 `cursor: "pointer"` 를 다시 쓰지 않는다.

3. **비활성에는 이유가 따라온다.** 컨트롤을 비활성으로 만드는 쪽이 그 이유 문자열(i18n)을 함께 계산해 `title` 로 준다. 업데이트 확인 버튼의 이유는 세 갈래다 — 상태 미도착, dev 빌드 게이트, 진행 중. 별도 문단의 설명은 유지하되 그것을 유일한 통로로 쓰지 않는다. 이유를 만들 수 없다면 그 컨트롤은 비활성이 아니라 숨겨야 한다.

4. **앱을 떠나는 버튼은 그렇게 보인다.** OS 브라우저로 클릭을 넘기는 버튼은 external-link 아이콘(사각형 + 나가는 화살표)을 앞에 달고 `title` 로 "브라우저에서 엽니다"를 말한다. 클릭 후가 아니라 클릭 전에 알린다.

5. **아이콘은 `components/ui/icons.tsx` 의 인라인 SVG 다.** 아이콘 폰트나 아이콘 패키지를 도입하지 않는다 — 현재 앱의 글리프는 십여 개이고, 각 글리프는 `stroke="currentColor"` 로 그려져 버튼의 색과 비활성 투명도를 그대로 상속한다. 컴포넌트 파일에 SVG 를 직접 붙여넣지 않고 이 파일에 모아, 두 번째 호출 지점이 같은 그림을 재사용하게 한다. 글리프 수가 이 방식으로 관리하기 어려운 규모가 되면 아이콘 패키지 도입은 그때 별도 결정으로 다룬다(entry chunk 예산이 그 결정의 주요 force 가 된다).

6. **dev 빌드 게이트는 그대로다.** UI 는 그 게이트를 설명할 뿐 우회하지 않는다. `enabled` 는 계속 Rust 가 소유하고, 프론트엔드는 그 값으로 버튼을 비활성화하고 이유를 말한다.

## Alternatives Considered

- **CSS 클래스만 추가하고 컴포넌트는 만들지 않는다**: `.ui-btn ui-btn-primary` 를 각 호출 지점이 직접 쓰면 파일이 하나 줄어든다. 그러나 아이콘 슬롯·`type="button"`·클래스 조합이 호출 지점마다 반복되고, 그 반복이 지금의 인라인 조립을 만든 원인이다. 얇은 컴포넌트가 그 반복을 한 곳에 둔다.
- **dev 빌드에서도 확인 버튼을 살린다**(설치만 막는다): "눌렀는데 아무 일도 없다"가 사라진다. 채택하지 않는다 — 확인이 성공하면 UI 는 설치를 제안하게 되고, 그 제안이 debug 바이너리에서는 실행될 수 없다. 막힌 경로를 더 깊은 곳에서 막는 것은 설명을 더 늦추는 것이다.
- **비활성 대신 버튼을 숨긴다**: 오해가 원천적으로 없다. 그러나 "이 앱에 업데이트 확인이 있다"는 사실 자체가 사라져 dev 빌드에서 기능 존재를 확인할 수 없다. 이유를 말할 수 있는 경우에는 비활성 + 설명이 더 많은 정보를 준다.
- **클릭 시 alert/알림으로 이유를 띄운다**: 발견성이 가장 높다. 채택하지 않는다 — 비활성 컨트롤은 클릭 이벤트를 받지 않는 것이 표준 동작이고, 그것을 살리려면 `disabled` 를 버리고 가짜 비활성을 만들어야 한다. 모달은 dev 자동화 루프도 세운다.
- **Google Material Icons / lucide 등 아이콘 패키지 도입**: 아이콘이 필요할 때마다 손으로 그리지 않아도 되고 시각적 일관성이 보장된다. 지금은 채택하지 않는다 — 필요한 글리프가 하나이고, entry chunk 가 이미 크기 예산에 붙어 있어(`build/chunk-groups.ts`) 트리 셰이킹 여부와 별개로 의존성 하나를 추가할 근거가 약하다. 아이콘 수요가 늘면 이 항목을 다시 연다.
- **`title` 대신 항상 보이는 인라인 설명**: tooltip 은 hover 를 요구한다. 그러나 비활성 이유는 세 갈래이고 그중 둘은 일시적(상태 미도착, 진행 중)이라 항상 보이는 문구로 만들면 레이아웃이 흔들린다. 영구적인 이유(dev 게이트)는 이미 문단으로도 보여 준다.

## Consequences

- 비활성 버튼이 비활성으로 보이고, hover 하면 왜 못 누르는지 말한다. dev 빌드에서 정상 동작하는 안전장치가 고장으로 신고되는 경로가 닫힌다.
- 업데이트 섹션의 버튼 5개가 링크 모양에서 실제 버튼으로 바뀐다. `primary` 는 화면당 하나(확인 / 설치)라는 규칙이 생기므로, 이후 이 섹션에 액션을 추가할 때 무엇이 primary 인지 정해야 한다.
- 공용 `Button` 과 `.ui-btn*` 가 생겼지만 이번 PR 은 업데이트 섹션만 옮긴다. 나머지 화면의 인라인 버튼은 남아 있어, 당분간 두 표현이 공존한다. 새 버튼은 공용 쪽만 쓰고, 기존 버튼은 그 화면을 손댈 때 함께 옮긴다.
- 아이콘이 `icons.tsx` 로 모이기 시작한다. 이미 각 컴포넌트에 흩어져 있는 인라인 SVG 들은 그 컴포넌트를 손댈 때 옮기며, 지금 일괄 이동하지 않는다.
- `title` 은 터치 표면에서 보이지 않는다. Remote/모바일 표면이 같은 컨트롤을 갖게 되면 비활성 이유를 그 표면에서 어떻게 말할지 다시 결정해야 한다.
