# 0380. Remote 언어는 기기가 소유하고 제품 문구만 명시적으로 번역한다

- Status: Proposed
- Date: 2026-11-09
- Source: [이슈 #1297](https://github.com/kochul2000/laymux/issues/1297), [api-contracts.md 언어 설정·§13.4](../architecture/api-contracts.md), [ADR-0209](0209-remote-display-preferences-are-device-local.md), [ADR-0214](0214-remote-settings-paginates-into-tabs.md)
- Extends: ADR-0209의 기기 로컬 표시 선호에 언어 선택을 추가한다.

## Context

Remote는 영어 HTML·동적 상태 문구, 한국어 워크트리·공유 첨부, 개별 브라우저 언어를 따르는 키보드 토스트·OAuth 중계를 함께 표시했다. 같은 문서 안에서도 언어가 달라지고 사용자는 이를 고칠 수 없었다. PC 설정의 언어를 쓰면 접속 기기마다 다른 사용 언어를 유지할 수 없다.

Remote에는 터미널 출력, 메모 초안, 파일 내용·경로, 사용자가 정한 이름이 함께 있다. DOM 문자열을 사전과 대조해 일괄 치환하면 사용자 콘텐츠가 제품 문구와 같을 때 오염된다. 언어를 바꾸려고 페이지를 다시 읽는 방식도 연결·초안·도구 상태를 잃게 한다. 번역 범위는 제품 문구이며, 사용자·호스트가 제공한 데이터와 외부 오류의 진단 세부는 범위 밖이다.

## Decision

**Remote 언어 선택은 브라우저 origin별 기기 선호로 소유하며, 번역은 명시적으로 만든 제품 문구 토큰과 HTML 표식에서만 수행한다.**

- `localStorage["laymux.remote.language"]`는 JSON 문자열 `"system" | "ko" | "en"`을 저장한다. 누락·손상·알 수 없는 값은 `system`이다. `system` 해석은 PC와 같은 순수 `resolveLanguage()`를 재사용한다. `ko*`는 한국어이고 나머지는 영어다. PC 설정·Remote API·lease와 독립적이며 PC 언어를 바꾸거나 가져오지 않는다.
- App의 언어 선택은 문서 `lang`, 정적 제품 문구, 열린 화면의 동적 제품 문구·상태·접근성 속성에 즉시 반영한다. 새로고침·네트워크 요청·도구 재초기화를 하지 않으며 입력·선택·포커스·편집 초안을 보존한다. 저장 실패 시 문서에서 적용하고 저장 불가 상태를 알린다.
- Remote 전용 공통 사전과 포매터를 사용한다. PC의 React i18next singleton을 import하지 않는다. 기존 PC 업데이트 단계 문구는 공유 순수 사전을 같은 토큰 경계로 연결한다. 기기별 OAuth·키보드 언어 판정은 별도로 두지 않는다.
- `t()`와 보간 템플릿은 원문 키와 보간값을 보관하는 제품 토큰을 만든다. 보간한 사용자 값은 번역하지 않는다. 일반 문자열은 같은 내용이 사전에 있어도 제품 토큰으로 취급하지 않는다. DOM setter는 제품 토큰일 때만 현재 언어로 표시·등록하고, 일반 문자열로 덮어쓰면 등록을 해제한다. 정적 HTML은 작성자가 붙인 `data-remote-i18n*` 표식만 번역한다.
- 바인딩은 `WeakMap`에 저장하고 언어 변경 시 현재 문서의 관리 표식만 순회한다. 제거한 노드를 강하게 보관하거나 `MutationObserver`로 임의 텍스트를 감시하지 않는다. `textContent`/속성 setter를 사용하므로 보간값은 HTML로 해석되지 않는다.

## Alternatives Considered

- **PC 언어를 Remote로 전파:** 기기 선호를 PC 설정에 종속시키고 연결 전 기본값과 lease 외 소유권을 추가한다. ADR-0209의 기기 경계에 맞지 않는다.
- **독립 i18next 인스턴스:** 언어 엔진 분리는 가능하지만 DOM에 사용자 데이터와 제품 문자열을 구분하는 명시 경계는 여전히 필요하다. 두 언어와 개수·값 보간에 필요한 작은 포매터를 채택한다. 복잡한 문법·복수형 언어를 추가하면 재검토한다.
- **모든 DOM 문자열을 사전과 대조:** 사용자가 입력한 `Settings` 같은 값도 바뀌고 터미널·파일 내용이 훼손된다. 관리 대상만 표시한다.
- **언어 변경 후 새로고침:** 초기화 시점 상수를 다시 만들기는 쉽지만 초안과 연결에 불필요한 영향을 준다. 지연 평가 토큰을 사용해 열린 DOM만 갱신한다.

## Consequences

- LAN·Tailscale·Cloud 등 origin이 다르면 선택도 별개이며 사이트 데이터를 지우면 `system`으로 돌아간다. 언어 동기화 API와 마이그레이션은 추가하지 않는다.
- 새 제품 문구는 공통 사전·토큰 또는 정적 HTML 표식에 등록해야 한다. 제품 토큰을 문자열 연결·조기 `String()` 변환으로 소실시키지 않고 보간 템플릿을 사용한다. ID·키캡·프로토콜·아이콘 이름은 번역하지 않는다.
- 테스트는 사전 대칭·보간, 저장 복원/실패, 문서 lang, 정적·동적·접근성 갱신, 사용자 문자열 충돌, 열린 도구와 초안 보존, 기기 언어별 실제 Remote 자산 렌더링을 검증한다. 번들 입력 해시에 사전와 포매터·공유 언어 해석을 포함한다.
