# 0295. Codex 대화 귀속을 평상시 저장과 종료 확인이 공유한다

- Status: Accepted
- Date: 2026-10-06
- Source: 사용자 PC 재부팅 후 대화 복원·종료 지연 수정 및 dev/TDD 검증 요청, [ADR-0222](0222-agent-session-checkpoint-coordinator.md), [ADR-0292](0292-codex-hook-lifecycle-session-proof.md), [ADR-0294](0294-codex-process-bound-lifecycle-proof.md), architecture/data-flow.md §13.5
- 관계: ADR-0292·0294의 대화 증거를 일반 checkpoint까지 확장하고, 복원 증거의 훅 설치 재검사 의존성을 대체한다. 입력 fence·generation·중복 소유권·원자적 저장 계약은 ADR-0222를 유지한다.

## Context

종료 시점에만 훅 대화를 일반 귀속 결과에 합치면 평상시에는 정확한 ID를 알아도 복원점으로 저장하지 못한다. 공유 Codex 서버의 진단이 현재 TUI를 특정하지 못하면 일반 저장이 미식별로 분류되어 기존 복원점까지 지운다. 종료 확인은 pane마다 전체 프로세스·진단·훅 설치·rollout을 반복 조회하고, 설치 검사 오류를 증거 부재로 바꾸어 화면 `/status`를 실행한다. 따라서 실제 대화와 무관한 WSL 설치 조회 지연도 종료 실패로 이어진다.

요구사항은 전원이 꺼진 뒤 디스크에 저장된 대화로 복원하는 것이다. 실행 중 프로세스 유지와 PTY 데몬 분리는 범위 밖이다. 잘못된 대화를 자동으로 여는 것, 저장하지 못한 최신 상태를 저장 성공으로 알리는 것은 허용하지 않는다.

## Decision

**Codex의 현재 대화 증명은 일반 귀속 조회에서 수행하고, 자동 저장과 종료 확인이 같은 결과를 사용한다.**

- Rust가 현재 PTY generation·실제 Codex 프로세스·실행 환경·관리된 live OSC 제목과 훅의 유일한 전체 ID를 대조한다. 프로세스 진단의 정확한 선택과 제목이 충돌하면 미확인으로 처리한다. 훅의 수신 pane ID, 과거 저장 ID, CWD, 최신 파일을 대체 증거로 사용하지 않는다.
- 훅 우선 모드에서만 제목·훅 연결을 일반 귀속에 합친다. 해당 프로세스의 저장소에서 정확한 최상위 rollout을 확인하며, 훅 ID의 파일 부재를 Fresh로 합성하지 않는다. Fresh는 기존 프로세스 lifecycle의 새 대화 증거를 요구한다. I/O 뒤 title revision·generation을 다시 확인한다.
- 앱이 검증해 실제 PTY에 전달한 Codex resume 요청은 generation에 결부된 후보 ID로 유지한다. 현재 Codex 프로세스·live OSC 제목·정확한 최상위 rollout이 모두 그 ID와 일치할 때만 새 훅 없이 현재 대화를 확인한다. 일반 입력 뒤에도 이 후보 대조는 가능하지만, ADR-0232의 미소비 요청만으로 인정하는 RestorePending 유예를 되살리지는 않는다. `/new`·다른 `/resume` 제목은 이전 후보를 사용할 수 없고, 제목이 아직 없거나 파일 검증이 실패하면 Unknown이다. 저장된 settings 값 자체나 과거 화면을 증거로 사용하지 않는다. 이는 Codex 0.160.1 공유 서버의 resume 직후 훅·TUI 진단이 없는 실제 재기동 시나리오를 지원한다.
- 이미 수신한 대화 증거의 유효성은 현재 프로세스·제목·저장소로 판단한다. 훅 설치 파일의 현재 상태는 설치 관리와 작업 상태 감지의 책임이며, 확정된 대화를 저장할 때 helper를 다시 실행하는 조건으로 사용하지 않는다.
- 훅 관찰과 대화 제목 변경은 중앙 checkpoint coordinator에 합쳐지는 저장 힌트다. 힌트 자체는 ID를 저장하지 않는다. 디스크 SoT는 기존 settings.json이고, 읽기 실패는 Unknown으로 마지막 저장값을 보존한다. 확인된 대화 전환·종료·모호성은 기존의 보수적인 복원 정책을 유지한다.
- 종료 확인은 일반 귀속이 확인한 대화와 현재 프로세스·제목을 재검증한다. 전체 프로세스·대화 조회를 pane마다 중첩 실행하지 않고 조회 단위로 공유한다. 증거 없는 pane만 기존 fenced `/status` 경로를 사용한다. 휴리스틱 모드와 종료 확인 비활성 옵션의 계약은 유지한다.
- `/status`의 부가 필드 이름·순서·누락·메타데이터 줄바꿈은 대화 증거의 조건이 아니다. 현재 builtin 응답의 헤더와 유일한 `Session`/`Session ID` 전체 UUID를 확인하고 실제 rollout에 대조한다. 과거 카드, 중복/잘린 UUID, 다른 응답·모달, 다른 generation·sequence·geometry는 계속 거부한다. ADR-0278의 부가 필드 목록·순서 검사는 이 최소 정체성 계약으로 대체한다.
- 두 번의 critical 관측·원자적 파일 교체·저장 후 인터럽트 순서를 유지한다. 실패한 최종 검증은 종료·업데이트를 중단하고 입력 fence를 해제한다. 평상시 저장은 문제가 있는 pane 때문에 정상 pane의 디스크 저장을 포기하지 않는다.
- Windows native와 WSL에 같은 증거 규칙을 적용한다. 저장소·프로세스 조회 오류는 해당 pane에 결부하고 진단 이유를 기록한다. 재시작은 메모리 증거를 재사용하지 않고 디스크 복원점에서 새 PTY와 새 Codex 프로세스를 만든다.

## Alternatives Considered

- `/status` timeout 증가: 정상 저장과 종료 저장의 증거가 다른 문제를 해결하지 못하고 실패까지 대기만 늘린다.
- PTY 데몬 분리: 앱 재시작 중 프로세스 유지에는 유효하지만 PC 재부팅 이후 대화 복원에는 별도의 디스크 저장이 여전히 필요하다.
- 마지막 훅 ID 무조건 저장: 공유 서버의 과거 pane 환경과 늦은 이벤트가 다른 pane에 잘못 귀속된다.
- 설치 결과를 장기 캐시해 종료에 사용: 캐시 무효화 책임을 추가하지만 현재 대화의 소유권 증거는 강화하지 않는다.
- 미식별이면 항상 마지막 ID 복원: `/new`·`/resume` 전환 뒤 이전 대화가 다시 열릴 수 있다.

## Consequences

정상 훅 대화는 실행 중에 복원점이 저장되고 종료 때 입력 초안을 건드리지 않는다. 설치 파일 읽기 지연을 종료 경로에서 제거하고 중첩 조회를 줄인다. 대신 일반 귀속에 훅 연결과 I/O 이후 무효화 검사가 필요하며 저장 힌트의 합치기·종료 fence 간 경합을 검증해야 한다. 훅 누락·제목 충돌·잘못된 rollout은 여전히 보수적으로 실패한다. 저장 완료 전 전원 차단에서 최신 턴까지 보장하지 않는다.

설정 마이그레이션은 없다. [회귀 시나리오](../codex-continuous-checkpoint-validation.md)에서 자동화와 dev 실기 결과를 분리해 기록한다. Codex의 제목·훅·진단 형식이 바뀌거나 정상 pane에서 반복적으로 fallback이 발생하면 증거 계약을 재검토한다. 기존 복원 기능의 정확성과 종료 지연 수정이므로 버전 영향은 patch다.
