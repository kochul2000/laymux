# 0315. Remote 복원 링크의 셸 판정은 탭 시점의 호스트 상태만 쓴다

- Status: Accepted
- Date: 2026-10-11
- Source: 사용자 보고("코덱스, 클로드, 그록? 종료시 보여주는 resume 을 클릭커블하게 파싱하는 동작이 리모트에선 안돼", "안드로이드고, 밑줄이 안뜬다", "해당행은 ctrl c 로 종료 복귀후 화면에 남은 행"), [ADR-0286](0286-clickable-agent-resume-hints.md)
- 관계: ADR-0286의 Remote 규칙 "셸 상태를 조회 전후 검사한다"를 바로잡는다. 조회 전 검사는 Remote가 들고 있는 navigation 스냅샷이 아니라, 탭할 때 다시 읽은 호스트 상태로 대체한다. 나머지 검사 항목(lease·terminal·출력 generation·출력 준비·셀 유효성의 조회 전후 검사)과 제출 경로는 그대로 둔다.

## Context

ADR-0286은 Remote가 복원 링크를 탭했을 때 셸 상태를 호스트 설정 조회 전후에 모두 검사하도록 했다. 조회 전 검사에는 Remote가 마지막으로 받은 navigation 스냅샷의 activity·commandRunning 값을 썼다.

그런데 Remote는 이 스냅샷을 drawer가 열려 있는 동안에만 주기적으로 다시 읽는다. heartbeat은 스냅샷을 갱신하지 않는다. 에이전트가 실행 중일 때 받은 스냅샷은 activity를 `interactiveApp`(Claude·Codex)으로 계속 들고 있다. 그래서 사용자가 Ctrl+C로 에이전트를 끝낸 뒤 화면에 남은 복원 안내를 탭해도 조회 전 검사에서 셸이 아니라고 판정되어, 호스트 조회 없이 아무 반응이 없었다. 터치에는 hover가 없으므로 밑줄도 탭하는 순간에만 잠깐 나타났다가 사라진다. 데스크톱은 activity를 실시간 store에서 읽으므로 같은 상황에서 동작한다.

## Decision

**Remote 복원 링크의 셸 판정은 탭할 때 다시 조회한 호스트 navigation의 해당 terminal 상태(activity가 `shell`이고 명령 실행 중이 아님)만 사용한다. Remote가 보관한 navigation 스냅샷으로는 셸 여부를 판정하지 않는다.**

- 조회 전에는 탭이 유효한지만 검사한다: 출력 준비, terminal, lease, 중복 제출 여부.
- 조회 후에는 호스트 셸 상태, 그리고 terminal·lease·출력 generation·출력 준비·셀 유효성이 조회 전과 같은지 검사한다. 하나라도 어긋나면 제출하지 않는다.
- 호스트가 아직 에이전트나 명령을 실행 중이라고 답하면 입력하지 않는다. 그 프로세스에 명령을 타이핑하지 않기 위해서다.

## Alternatives Considered

- **drawer가 닫혀 있어도 navigation을 주기적으로 갱신한다:** 모든 Remote 화면에 상시 폴링 비용이 생긴다. 갱신 간격 안에 탭하면 여전히 낡은 값을 보게 되므로 선택하지 않았다.
- **조회 전 로컬 검사를 유지하되, 실패하면 navigation을 다시 읽고 한 번 더 판정한다:** 결국 호스트 조회가 판정을 맡게 되고, 같은 판정을 두 경로로 나눠 갖게 되므로 선택하지 않았다.
- **에이전트 종료를 Remote로 push한다:** 새 wire 계약이 필요하다. 탭 시점 조회만으로 정확한 판정을 얻을 수 있으므로 이번 범위에서는 선택하지 않았다.

## Consequences

- 에이전트를 Ctrl+C·`/exit` 등으로 끝낸 직후 남은 복원 안내를 Remote에서 탭하면, drawer를 열어 갱신하지 않아도 바로 재개 명령이 제출된다.
- 에이전트가 실행 중일 때 탭해도 호스트 조회 한 번이 발생한다. 이 조회는 탭할 때만 일어나고, 제출은 하지 않는다.
- 검증: 스냅샷은 에이전트 실행 중이고 호스트는 셸로 돌아온 상태에서 탭하면 제출하는 e2e를 둔다. 호스트가 에이전트 실행 중이면 제출하지 않는 e2e도 둔다. 단위 테스트는 로컬 문맥에 셸 상태가 없어도 호스트 판정으로 제출하는지 확인한다.
