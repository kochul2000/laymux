# 0239. Remote 방향 패드는 중앙 길게 누르기로 이동하고 불투명도를 기기에 저장한다

- Status: Accepted
- Date: 2026-09-07
- Source: 사용자 실기 피드백과 최종 승인, [api-contracts.md §13.4](../architecture/api-contracts.md#134-terminal-control), [ADR-0237](0237-remote-floating-input-controls.md)
- 관계: ADR-0237의 별도 손잡이·좌표 편집 정책을 대체하고 기기 로컬 불투명도를 추가한다. 액션 실행·권한·위치 소유권은 유지한다.

## Context

플로팅 방향 패드의 별도 이동 손잡이는 작은 화면을 차지하고 방향 입력과 별개인 버튼처럼 보인다. 사용자는 원형 패드의 중앙을 길게 눌러 이동하고 좌표 입력 대신 불투명도를 조절하기를 원한다. 일반 방향키와 pane/미확인 알림 이동은 기본 아이콘뿐 아니라 사용 중 방향 표시도 구분해야 한다. 별도 pane 전용 패드는 필요 없다.

## Decision

**원형 패드는 중앙 길게 누르기로 이동을 시작하고, 불투명도는 기존 기기 로컬 플로팅 설정에 저장한다.**

- 패드 중앙에서 길게 누르면 이동으로 전환한다. 그 전에 이동 임계값을 넘으면 기존 플릭 입력으로 처리하며, 이동으로 전환된 제스처는 입력을 보내지 않는다. 취소는 이전 위치를 복원한다. 일반 버튼은 기존 직접 드래그를 유지한다.
- 설정의 X/Y 입력을 제거하고 이동 방법을 안내한다. 정규화 좌표는 기존대로 드래그 위치 영속에 사용한다.
- 패드와 일반 버튼 각각 `opacity`를 0–1 범위로 저장한다. 누락·잘못된 값과 새 버튼의 기본값은 0.5이며 명시적으로 저장된 값은 보존한다. 설정은 0–100%로 표시한다. 별도 마이그레이션은 만들지 않는다.
- 사용자 요구에 따라 플로팅 버튼은 원형으로 표시한다. 이는 일반 UI 반경 규칙의 예외다. 상시 강조색과 브라우저 기본 탭 하이라이트를 사용하지 않는다.
- 일반 방향키의 기본 아이콘은 Lucide Move, pane/알림은 GamepadDirectional이다. 사용 중 힌트는 각각 ArrowUp/Down/Left/Right와 SquareChevronUp/Down/Left/Right를 해당 방향에 표시한다. 힌트는 Keys 행 표시 여부와 독립적이다.
- 기존 입력·navigation 경로와 lease 검증을 재사용한다. Remote/Automation API 변경은 없다.

## Alternatives Considered

- 별도 손잡이·X/Y 입력 유지: 사용자가 실기에서 거부했고 좁은 화면의 조작 요소만 늘어난다.
- 즉시 드래그로 패드 이동: 방향 플릭과 충돌하므로 중앙 길게 누르기로 의도를 구분한다.
- 불투명도 호스트 저장: 기기별 배치·가시성 선호이므로 기존 기기 로컬 소유권에 맞지 않는다.

## Consequences

손잡이 없이 원형 패드만 남고 터미널 가림을 조절할 수 있다. 길게 누르기 발견성은 설정 안내가 보완한다. 0%는 보이지 않는 컨트롤을 남기지만 설정에서 불투명도 복원·비활성화할 수 있다. 플릭·반복·이동·취소 분리, 기본값·저장값, 힌트의 행 독립성을 브라우저 테스트로 검증한다. 플랫폼별 길게 누르기 감도가 맞지 않으면 이동 지연을 재검토한다.
