# 0235. 줄바꿈 경로의 논리 줄과 물리 셀 매핑

- Status: Proposed
- Date: 2026-09-06
- Source: 사용자 Screenshot_20260906_191830_Laymux.jpg 버그 신고, [ADR-0188](0188-path-link-ambient-detection-triggers.md), [ADR-0191](0191-path-link-space-extended-candidates.md), architecture/data-flow.md §8.6
- Extends: ADR-0188 (surface-local 후보 입력과 표시 범위)

## Context

화면의 한 경로가 두 줄 이상에 걸치면 물리 줄마다 추출한 접두 디렉터리와 상대경로 뒷부분이 서로 다른 링크가 된다. xterm 선택은 자동 줄바꿈을 제거하므로 선택 문자열의 줄 번호를 물리 줄 번호에 더하는 방식도 틀린다. 한글·이모지·결합 문자는 문자열 길이와 셀 폭이 다르다.

자동 줄바꿈은 xterm의 `isWrapped`로 알 수 있지만 TUI가 직접 출력한 개행은 의도를 확정할 정보가 없다. 임의의 개행 제거는 독립 파일 목록을 다른 경로로 바꿀 수 있다. 기존 배치 stat 상한과 발견/실행 분리는 유지해야 한다.

## Decision

**두 surface는 공통 셀 기반 논리 줄 복원기를 사용하고, 경로 하나의 물리 줄 조각을 동일 대상으로 표시·검증한다.**

- 자동 줄바꿈은 공백을 삽입하지 않고 이어 붙인다. 실제 출력된 공백은 보존하고 xterm의 빈 패딩 셀만 제외한다.
- hard wrap은 앞줄 경로 토큰이 오른쪽 끝(최대 1셀 여유)에 닿고 다음 줄의 들여쓰기가 같으며, 앞 토큰이 완성된 확장자로 끝나지 않고 후속 토큰에 구분자·점이 있으며 새 절대경로·URL이 아닐 때만 결합한다. 일반 개행·빈 줄은 결합하지 않는다. 이 휴리스틱은 확정 문법이 아니며 실제 존재 여부는 기존 stat이 판정한다. xterm이 탭을 셀 공백으로 펼친 뒤에는 출력된 스페이스와 구분할 수 없다.
- 읽기는 최대 64개 물리 줄·8192 UTF-16 문자로 제한한다. point는 앞뒤 8줄의 제한된 문맥을 사용한다. 자동 줄바꿈 그룹이 읽기 경계에서 잘렸으면 그 그룹 전체를 버린다. 명시적 선택은 선택 범위만 읽는다.
- 파서는 복원한 논리 줄과 offset만 받는다. 경로 정규화·CWD·겹침 해소·stat 책임과 Remote 요청/응답 shape는 유지한다. Remote `lines`는 물리 화면 행이 아니라 surface가 복원한 논리 줄이다. 셀 좌표는 호스트에 보내지 않는다.
- 후보의 UTF-16 offset은 원래 각 물리 줄의 셀 범위로 되돌린다. 모든 조각은 하나의 검증된 전체 경로를 연다. 조각 중 하나라도 원문·폭·wrap 상태가 변하면 전체 링크를 폐기한다. 마커의 scrollback 이동량은 모든 조각에 함께 적용한다.

## Alternatives Considered

- 정규식에서 모든 개행 제거: 독립 파일 목록을 합치고 좌표를 잃으므로 기각한다.
- Remote에만 복사 구현: desktop 선택·hover에서도 같은 오류가 남으므로 기각한다.
- 서버에 물리 좌표와 wrap 메타데이터 전달: surface-local 좌표 책임을 서버로 확장할 필요가 없으므로 기각한다.
- 자동 wrap만 지원: 신고된 TUI hard wrap이 남으므로 제한된 휴리스틱을 함께 사용한다.

## Consequences

기존 파서와 batch stat을 재사용하면서 두 줄 이상의 경로 전체를 열 수 있다. 한글·이모지의 셀 폭과 부분 선택을 실제 xterm 테스트로 검증한다. 비용 상한 밖의 매우 긴 줄은 링크를 만들지 않는다. 실제 개행이 우연히 hard-wrap 조건을 만족하면 결합 후보가 생길 수 있으므로, 출력 형식의 명시적 메타데이터가 제공되면 휴리스틱을 대체한다. 파일명 자체의 개행과 프로그램의 레이아웃 개행은 화면만으로 구분할 수 없다. 새 설정·마이그레이션은 추가하지 않는다.
