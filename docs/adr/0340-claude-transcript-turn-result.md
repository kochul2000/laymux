# 0340. Claude 턴의 종료 결과는 작업 시작 기준점 이후의 대화 기록으로 판정한다

- Status: Proposed
- Date: 2026-10-17
- Source: 사용자 요구("클로드 코덱스 다르단 점은", 대화 기록 판정안 선택), Codex PR #1227 리뷰(P2 4건), [ADR-0250](0250-terminal-task-state-and-notification-transitions.md), [ADR-0321](0321-agent-session-record-fills-unconfirmed-task.md), [ADR-0248](0248-codex-turn-lifecycle-activity.md), [ADR-0283](0283-opt-in-hook-task-state.md), [ADR-0118](0118-codex-session-pid-attribution.md), [ADR-0120](0120-wsl-agent-session-attribution.md), [ADR-0005](0005-display-state-raw-separation-compute.md), [hook 검증](../agent-hooks-validation.md)
- 보완: ADR-0250 Decision "앱별 신호의 인정 범위"의 Claude 행(`✳`만으로 성공·중단을 구분하지 않음)에 결과 관측 경로를 추가한다. ADR-0250:60이 별도 설계를 요구한 "세션에 귀속된 structured lifecycle 관측"을 Claude 결과에 한해 정한다. ADR-0321의 작업 상태 판정과 기각 사유(상태 신호로서의 대화 기록)는 유지한다.

## Context

ADR-0250은 종료를 성공·실패·중단·결과 미관측으로 구별하라고 정했다. 그런데 앱마다 결과를 얻는 경로가 다르다.

| 앱      | 결과 출처                                            | 성공     | 실패             | 중단                              |
| ------- | ---------------------------------------------------- | -------- | ---------------- | --------------------------------- |
| 통합 셸 | OSC 133 D의 종료 코드                                | 관측     | 관측             | 결과 미관측(PowerShell `Stopped`) |
| Codex   | rollout 턴 기록(ADR-0248)                            | 관측     | 관측             | 관측                              |
| Grok    | `updates.jsonl` `turn_completed`(ADR-0321)           | 관측     | —                | 관측                              |
| Claude  | `✳` title, `sessions/<pid>.json` `status`, 선택적 훅 | **없음** | StopFailure 훅만 | **없음**                          |

Claude 턴은 정상 종료든 Esc 중단이든 거의 언제나 "결과 미관측"이 된다. `✳`과 `status: idle`은 입력 가능 상태로 돌아왔다는 관측일 뿐이다. 훅의 Stop은 ADR-0283에 따라 "응답 종료 관찰"이다. 다른 사용자 Stop 훅이 작업을 계속시킬 수 있기 때문이다. Claude에는 Esc 중단 전용 훅도 없다. 그래서 같은 상황에서 Codex는 `✓`이고 Claude는 결과 미관측이 된다. 사용자에게는 앱마다 의미가 다른 표시로 보인다.

Claude Code는 대화를 `<설정 루트>/projects/<프로젝트 디렉터리>/<sessionId>.jsonl`에 줄 단위로 덧붙여 기록한다. 이 파일은 `sessions/<pid>.json`(ADR-0118·0120의 귀속 파일)과 같은 설정 루트에 있다. 2.1.300·2.1.301 Windows 실측에서 턴 끝은 다음과 같이 남는다.

- **정상 종료:** `type: system, subtype: stop_hook_summary` 다음에 `type: system, subtype: turn_duration`이 기록된다. 실측한 246턴 모두 이 두 기록이 짝을 이뤘다.
- **API 오류:** `isApiErrorMessage: true`인 assistant 기록(`model: "<synthetic>"`) 다음에 `turn_duration`이 이어진다.
- **Esc 중단:** 본문이 `[Request interrupted by user]`(도구 실행 중에는 `… for tool use]`)이고 `interruptedMessageId`가 붙은 user 기록이 남는다. `turn_duration`은 기록되지 않는다. 2.1.293에는 같은 본문에 `interruptedMessageId`가 없는 기록이 있었다.

다만 파일 끝 부분만 보고는 **어느 턴의 경계인지** 확정할 수 없다. 첫 초안의 "끝에서 거꾸로 첫 경계를 찾는" 규칙은 Codex 리뷰가 실측 파일로 반례를 재현했다.

- 종료 관측이 대화 기록의 flush보다 먼저 올 수 있다. 다음 사용자 요청 줄이 아직 쓰이는 중이면, 그 앞에 있는 이전 턴의 `turn_duration`이 마지막 경계로 보인다.
- `turn_duration` 뒤에, 새 사용자 요청 없이 다른 부모 경로(`parentUuid`)의 assistant 기록이 이어질 수 있다. 예를 들어 백그라운드 도구가 끝나면 Claude가 스스로 이어서 작업한다. `isSidechain: false` 필터와 파일 순서만으로는 현재 경로를 고를 수 없다.
- `/model`, `/effort` 같은 로컬 명령과 그 출력은 `isMeta`가 없는 user 기록으로 남는다. 이를 턴 시작으로 분류하면 정상 종료 결과가 계속 가려진다.
- 훅 모드에서는 화면에 표시되는 작업이 훅 작업(`agentHook.task`)이다. 휴리스틱 작업에만 결과를 넣으면 화면에 반영되지 않는다. 같은 sequence로 결과만 다시 넣는 방법은 `observeTask`의 sequence 검사에 거부된다.

ADR-0321은 이 파일의 `turn_duration`을 **작업 상태** 신호로 검토했다가 기각했다. 대화 기록 저장을 끈 환경에서는 파일이 없고, 도구 실행과 권한 대기를 구분하지 못한다는 이유였다. 이 결정은 그 기각을 뒤집지 않는다. 상태는 계속 title·`status`·훅이 정하고, 대화 기록은 이미 끝난 작업의 **결과**만 채운다. 파일이 없으면 지금처럼 결과 미관측으로 남는다.

범위 밖:

- 셸 Ctrl+C를 중단으로 관측하는 것. OSC 133 D 확장이 필요하므로 별도 결정으로 다룬다.
- 결과별 아이콘·색상. ADR-0250이 후속 구현에 위임한 표시 결정이다.
- Claude 작업 상태(running·idle·waiting)의 판정 경로 변경.
- Grok·Codex의 결과 경로.

## Decision

**Claude 작업이 시작될 때 귀속된 대화 기록의 길이를 기준점으로 잡는다. 그 작업이 결과 없이 끝나면 기준점 이후에 덧붙은 완결된 기록에서 종료 경계가 정확히 하나일 때만 성공·실패·중단을 채운다. 그 밖의 경우에는 결과를 비워 둔다.**

### 기준점과 작업의 결합

- 결합 대상은 **표시 중인 작업**(`instance.task`, 훅이든 휴리스틱이든 선택 함수가 고른 것)이다. 이 작업이 새 `source`·`taskId`로 진행 중이 되면, 프론트는 그 식별자를 키로 Rust에 기준점을 요청한다.
- Rust는 현재 PTY generation과 기존 Claude 세션 귀속(PTY 자식 pid → `sessions/<pid>.json` → `sessionId`, ADR-0118·0120)으로 대화 기록 파일을 찾고, 그 시점의 파일 길이를 기준점으로 저장한다. 키는 terminal·generation·sessionId·작업 키다. 귀속 실패·중복 귀속·조회 실패에서는 기준점을 만들지 않는다.
- 이전 턴의 경계는 다음 요청보다 먼저 기록되므로 기준점 앞에 있다. 그래서 이전 턴의 결과를 현재 작업에 채우지 않는다. 사용자 요청·로컬 명령 기록을 턴 시작으로 분류할 필요도 없다.
- 기준점 요청은 작업 시작을 관측한 직후 한 번 보낸다. 시작이 늦게 관측되어 이번 턴의 경계가 이미 기준점 앞에 있으면 경계가 0개가 되고, 결과는 비어 남는다. 잘못된 결과는 만들지 않는다.

### 대화 기록 찾기

- 파일은 귀속 파일과 같은 설정 루트의 `projects/*/<sessionId>.jsonl` 중 이름이 정확히 일치하는 하나다. 일치하는 파일이 없거나 둘 이상이면 기준점을 만들지 않는다. CWD를 디렉터리 이름으로 바꾸는 Claude 내부 규칙을 재구현하지 않고, 최근 수정 시각이나 CWD로 다른 세션 파일을 추측하지도 않는다.
- WSL은 ADR-0120의 guest 경로 변환과 같은 HOME을 쓴다.
- 결과를 조회할 때 파일 길이가 기준점보다 짧거나 파일이 교체되었으면 결과를 내지 않는다.

### 경계와 결과

- 기준점부터 개행으로 끝난 줄만 읽는다. 쓰는 중인 마지막 줄은 읽지 않고, 다음 조회에서 이어 읽는다. 이미 읽은 위치와 누적 상태는 키별로 보관하므로 같은 바이트를 다시 읽지 않는다. 판정에 쓰는 필드(`type`, `subtype`, `uuid`, `parentUuid`, `isSidechain`, `isApiErrorMessage`, `interruptedMessageId`) 외의 내용은 보관하지 않는다.
- `isSidechain: true` 기록은 무시한다. 종료 경계는 둘뿐이다.
  - `turn_duration`: `parentUuid`를 따라 올라가 처음 만나는 assistant 기록이 `isApiErrorMessage: true`면 `failure`, 아니면 `success`다. 기준점 안에서 assistant 기록에 닿지 못하면 결과를 내지 않는다.
  - `interruptedMessageId`가 있는 중단 표지 user 기록: `interrupted`다. 본문 문자열만 같고 `interruptedMessageId`가 없으면 경계로 보지 않는다.
- 기준점 이후 경계가 **0개**면 아직 기록되지 않은 것이므로 보류한다. **정확히 1개**면 그 결과를 쓴다. **2개 이상**이면 laymux가 놓친 작업 경계(백그라운드 작업 뒤 자동 재개, Stop 훅의 계속 진행 등)가 섞인 것이므로 결과를 내지 않고 확정한다. 1개로 확정한 뒤 경계가 늘어나도 이미 채운 결과는 바꾸지 않는다.
- `success`는 ADR-0250·0248과 같이 **턴이 오류·중단 없이 정상으로 끝났다**는 뜻이다. 사용자의 목표를 달성했다는 뜻은 아니다. 중단 표지는 에이전트가 직접 남긴 기록이므로, ADR-0250이 금지한 "중단 키를 보냈다는 사실만으로 중단 확정"과 다르다.

### 결과 소유와 표시

- 결과는 별도 원시 상태로 둔다. pane별로 작업 키, 결과, 확정 여부를 저장한다(ADR-0005). 휴리스틱 작업과 훅 작업의 원시 관측은 바꾸지 않는다.
- 표시 작업 선택 함수만 결과를 합친다. 선택된 작업이 `ended`이고, 결과가 비어 있고, `source`·`taskId`가 결과의 작업 키와 같을 때만 결과를 붙인다. 훅 만료 등으로 선택이 다른 출처로 바뀌면 키가 달라지므로 붙이지 않는다. 이미 결과가 있는 작업(StopFailure 훅의 `failure` 등)은 덮지 않는다.
- 응답은 요청 시점과 generation·task epoch·선택된 작업의 `source`·`taskId`·sequence가 모두 같을 때만 반영한다. 그사이 새 작업이 시작되면 응답을 버린다.
- 결과 조회는 키에 맞는 작업이 결과 없이 끝난 동안 1초마다 하고, 결과를 채우거나, 2개 이상 경계로 확정하거나, 작업이 바뀌거나, 종료 후 10초가 지나면 멈춘다.
- 종료 알림은 ADR-0250대로 종료를 관측한 순간 한 번만 낸다. 그 순간 결과가 없으면 알림 문구에는 결과를 쓰지 않는다. 늦게 확인한 결과는 표시만 갱신하고 알림을 다시 만들지 않는다.

### 소유와 비용

- 파일 I/O와 경계 판정은 Rust가 소유한다. 프론트는 작업 키와 결과 원시값만 다루고, 대화 기록 형식을 해석하지 않는다.
- 기준점·누적 상태 레지스트리는 유계(pane 수 기준)이며, PTY generation 교체·세션 변경·작업 교체 시 버린다. 이 mutex는 AppState 락을 잡지 않은 채 취하는 leaf이고, 파일 I/O 중 AppState에 다시 들어가지 않는다(ADR-0248과 같다).

## Alternatives Considered

- **파일 끝에서 마지막 경계를 역방향으로 탐색(첫 초안):** flush 순서, 다른 부모 경로의 늦은 기록, 로컬 명령 기록 때문에 이전 턴 결과나 다른 경로의 결과를 현재 작업에 채운다. Codex 리뷰가 실측 파일로 재현했다.
- **user 기록을 분류해 턴 시작 판정:** 로컬 명령·`/compact`·백그라운드 재개마다 형식 규칙이 필요하고, 그 규칙은 공개 계약이 아니다. 기준점 방식은 분류 없이 "이 작업 이후의 경계"만 센다.
- **타임스탬프로 작업 구간 선택:** WSL guest와 호스트 시계가 다를 수 있고, 여유 시간을 두면 짧은 이전 턴이 섞인다.
- **parentUuid 사슬만으로 현재 leaf 추적:** 현재 leaf를 알려주는 공개 기록이 없다. `last-prompt.leafUuid` 같은 기록은 쓰이는 시점이 보장되지 않는다. 사슬은 `turn_duration`에서 실패 여부를 판정하는 데만 쓴다.
- **훅의 `transcript_path`와 UserPromptSubmit 시점을 기준점으로 사용:** 훅을 설치한 사용자에게만 동작하고, 휴리스틱 모드에는 같은 경로가 따로 필요하다. 한 경로로 두 모드를 덮는 편이 검증 대상이 적다.
- **Stop 훅을 성공으로 해석:** ADR-0283대로 Stop은 응답 종료 관찰이다. 다른 사용자 Stop 훅이 계속시킬 수 있다. 훅은 선택 설치이고, Esc 중단 훅도 없다.
- **신호 부재로 추론(Stop 뒤 재개가 없으면 성공, Stop 없이 `✳`면 중단):** 훅 전달 지연, 훅 미설치, title 비활성화에서 오판한다. ADR-0250은 무신호·무출력을 결과의 증거로 쓰지 않는다.
- **결과를 휴리스틱·훅 작업에 각각 써 넣기:** 원시 관측을 섞고, 같은 sequence 재관측은 거부된다. 별도 원시 상태와 선택 함수 결합이 ADR-0005와 맞는다.
- **셸·Codex도 "종료"로 낮춰 통일:** 이미 정확히 관측하는 결과를 버린다.

## Consequences

- Claude·Codex·Grok·통합 셸이 같은 결과 의미를 쓴다. Claude 결과 미관측은 대화 기록 저장을 껐거나, 귀속·형식 해석이 실패했거나, 시작을 늦게 관측했거나, 한 작업에 경계가 여럿 섞인 경우로 줄어든다.
- Claude 종료 알림 문구에는 대개 결과가 빠진다. 결과는 1초 조회 주기 안에 표시로만 채워진다. 알림 시점과 횟수는 바뀌지 않는다.
- Claude 작업이 시작될 때마다 세션 귀속 조회가 한 번 더 일어난다. 프로세스 snapshot과 WSL probe 재사용(ADR-0335)이 포함되며, ADR-0321의 1초 조회와 같은 비용이다.
- 대화 기록 파일은 수십 MB가 될 수 있다. 기준점 이후의 덧붙은 바이트만 한 번씩 읽으므로, 비용은 그 작업이 쓴 양에 비례한다.
- 대화 기록 형식은 공개 계약이 아니다. 필드가 바뀌면 결과를 내지 않고 이전처럼 결과 미관측으로 남는다. 결과를 잘못 채우지는 않아야 한다. Claude 버전이 바뀌면 다시 실측한다.
- laymux가 대화 파일을 읽게 된다. 판정에 필요한 필드만 쓰고 내용은 보관·전송하지 않는다는 점을 living doc에 남긴다.
- 후속 작업
  - 결과별 표시 분리(성공·실패·중단·결과 미관측·작업 없음·미확인). ADR-0250 위임 사항이다.
  - 셸 Ctrl+C 중단 관측(OSC 133 D 확장).
- 검증
  - Rust 단위 테스트: 기준점 이후 정상 종료·API 오류·Esc 중단(일반·도구 실행 중), 기준점 앞의 이전 턴 경계 무시, 쓰는 중인 줄의 이어 읽기, 경계 0개 보류와 2개 이상 확정, `interruptedMessageId` 없는 중단 문자열, sidechain 무시, 로컬 명령 기록 무시, parentUuid 사슬이 assistant에 닿지 못함, 파일 축소·교체·없음·중복 일치.
  - 프론트 단위 테스트: 선택된 작업 키에만 결합, 훅 모드 표시 반영, 출처 전환 시 미결합, 기존 결과 보존, 늦은 결과의 알림 미재발행, 새 작업 뒤 응답 폐기, 10초 뒤 조회 중단.
  - dev 실기(Windows·WSL Claude): 정상 턴의 성공, Esc 중단, 도구 실행 중 Esc, `/model` 뒤 결과 유지, 백그라운드 작업 뒤 자동 재개, 훅 모드의 Stop 뒤 성공, 사용자 Stop 훅이 계속 진행시킨 턴.
- 재검토 조건: Claude가 세션 파일이나 훅으로 턴 결과를 직접 제공하거나, 대화 기록의 턴 경계 형식이 바뀔 때.
