# 0312. PTY 데몬은 업데이트 재시작을 넘길 만큼만 세션을 유지한다

- Status: Proposed
- Date: 2026-10-10
- Source: 사용자 결정("데몬을 둔 이유는 업데이트 뿐이야", "T는 세팅.json - UI 없이 파일전용 값으로 넣어둬 10분 기본 값"), [ADR-0301](0301-pty-daemon-default-adoption.md), [ADR-0306](0306-pty-daemon-session-inventory.md), [ADR-0308](0308-pty-daemon-generations-across-updates.md), 이슈 #1157
- 관계: ADR-0301이 데몬에 둔 목적 가운데 "GUI가 crash해도 작업이 계속된다"를 "업데이트 재시작과 짧은 유예 동안만"으로 좁힌다. ADR-0306의 분리 세션은 사용자가 끝내던 것을 GUI가 자동으로 끝내도록 바꾼다.

## Context

PTY 데몬을 둔 이유는 업데이트 설치 동안 터미널 작업을 유지해, 재시작한 GUI가 이어받게 하는 것이다(ADR-0308). 그런데 지금 데몬은 세션이 있는 한 끝나지 않는다.

- GUI가 crash한 뒤 사용자가 GUI를 다시 열지 않으면, 셸과 에이전트는 로그오프하거나 재부팅할 때까지 화면 없이 계속 실행된다.
- 레이아웃이 저장되기 전에 GUI가 crash하면 어느 pane도 그 세션을 다시 붙이지 않는다(ADR-0306의 "분리" 세션). 사용자가 패널에서 끝내지 않으면 계속 남는다.
- 이 세션을 다시 보게 하자는 제안(#1157)이 있었지만, 목적이 업데이트뿐이라면 이런 세션은 보여 줄 대상이 아니라 정리할 대상이다.

## Decision

**데몬은 GUI 연결이 하나도 없는 상태가 유예 시간 동안 이어지면 세션을 모두 끝내고 종료한다. GUI는 실행 중에 데몬마다 presence 연결을 유지하고, 어느 pane도 붙이지 않을 분리 세션은 스스로 끝낸다.**

### 유예 시간

- `settings.json`의 `terminal.ptyDaemonGraceMinutes`다. 기본값은 10분이고 범위는 1~1440분이다. 설정 UI는 없는 파일 전용 값이다. 범위를 벗어나면 `validate_settings`가 `out_of_range`로 보고하고, 실행 경로는 값을 범위 안으로 맞춘다.
- 업데이트 설치와 새 GUI 기동을 넘길 만큼의 시간이다. GUI가 crash한 뒤 이 시간 안에 다시 열면 지금처럼 재결합된다(부수 효과).

### 데몬

- 세션이 있고 열린 연결이 하나도 없는 상태가 유예 시간 동안 이어지면, admission lock 안에서 다시 확인한 뒤 새 세션을 거절한다. 그다음 세션을 모두 끝내고 종료한다. 그 사이 연결이 하나라도 들어오면 처음부터 다시 센다.
- 유예 시간은 GUI가 보낸 presence가 알려 준다. 받은 적이 없으면 기본값(10분)을 쓴다.
- 세션이 없을 때의 idle 종료(60초)는 그대로다. 이때 presence 연결은 세지 않는다. 그래서 할 일이 없는 데몬은 GUI가 떠 있어도 끝난다.

### GUI presence

- GUI는 쓰는 데몬마다 presence 연결을 하나씩 유지한다. 시작하자마자 살아 있는 모든 호환 세대에 연결하고, 2분마다 다시 확인한다(데몬이 다시 떴을 수 있다). 터미널을 만들 때 쓰는 현재 세대와 재결합한 세대에도 연결한다. 첫 frame은 `Presence { graceMs }`이고, 연결은 GUI가 떠 있는 내내 열려 있다.
- 터미널 연결이 없어도 GUI가 있다는 것을 알리기 위해서다. 아직 열지 않은 워크스페이스의 세션(`awaitingPane`)이 대표적이다.
- 유예 값이 바뀌면 같은 연결로 다시 보낸다. GUI는 터미널을 만들 때와 2분마다 설정값을 읽는다(nextUse).
- 이 메시지를 모르는 이전 build 데몬은 연결을 닫는다. 그런 데몬에는 유예 규칙도 없다.

### 분리 세션 정리

- GUI는 시작하고 2분 뒤부터 2분마다 PTY 세션 목록을 분류한다(ADR-0306). 그리고 `detached`인 세션, 즉 어느 pane도 붙이지 않을 세션을 목록에 나온 attach epoch로 끝낸다.
- 주기는 idle 종료(60초)보다 길다. 정리할 때마다 모든 데몬에 연결하므로, 주기가 짧으면 빈 데몬의 idle 타이머가 계속 처음부터 다시 시작돼 끝나지 못한다.
- 저장된 상태가 file viewer를 다시 열면, viewer 터미널(`terminal-global-file-viewer:` 접두사, id는 프론트가 경로에서 만든다)도 붙을 pane을 기다리는 세션(`awaitingPane`)으로 본다.
- `awaitingPane`, `pane`, 다른 client가 잡은 세션은 건드리지 않는다. 목록 조회나 레이아웃 읽기가 실패하면 아무것도 끝내지 않는다.
- 첫 정리를 늦추는 것은 복원된 레이아웃의 pane이 먼저 자기 세션을 붙이게 하기 위해서다.

## Alternatives Considered

- **트레이 아이콘으로 남은 세션을 알림:** 데몬의 목적이 업데이트뿐이라면 오래 남는 세션은 보여 줄 대상이 아니다. 데몬에 UI 메시지 루프가 생겨 "PTY만 소유한다"는 경계(ADR-0300)도 넓어진다.
- **분리 세션을 새 pane에 다시 붙이는 기능(#1157):** 같은 이유로 필요 없다.
- **세션별 유예(분리된 시간 기준):** GUI가 떠 있는데도 아직 열지 않은 워크스페이스의 세션을 끝내게 된다. 기준은 "GUI가 있느냐"여야 한다.
- **GUI 설정 화면에 노출:** 사용자 결정에 따라 파일 전용 값으로 둔다.

## Consequences

- 업데이트는 지금처럼 세션을 유지한다(ADR-0308).
- GUI 없이 유예 시간이 지나면 데몬이 없던 때처럼 작업이 끝난다. 오래 걸리는 에이전트·빌드 작업도 마찬가지다.
- crash 뒤 레이아웃에 없던 세션은 다음 GUI가 2분 안팎에서 끝낸다. PTY 세션 패널의 수동 종료는 그 전에 쓸 수 있도록 남겨 둔다.
- 같은 build kind의 GUI 두 개가 같은 데몬 root를 쓰면(dev 워크트리 여러 개) 서로의 세션을 `detached`로 보고 끝낼 수 있다. ADR-0306이 이미 같은 전제("같은 build kind GUI 여러 개")를 두고 있다.
- 검증:
  - 데몬 테스트: 연결이 없으면 유예 뒤 세션이 끝나고 데몬이 멈춘다. presence가 있으면 터미널 연결이 없어도 유지된다. presence는 빈 데몬의 idle 종료를 막지 않는다. 유예 값은 범위 안으로 맞춰진다. GUI는 데몬당 presence를 하나만 연다.
  - 설정 테스트: 기본값 10과 범위 검증, 값이 없는 파일의 기본값.
  - dev 실기: 유예를 1분으로 두고 GUI를 끈 뒤 세션이 끝나는지, GUI가 떠 있는 동안 분리 세션이 정리되는지, 재결합이 유예 안에서 그대로 되는지 확인한다.
