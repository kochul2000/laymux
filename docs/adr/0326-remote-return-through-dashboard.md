# 0326. 원격 연결 복귀는 대시보드의 기존 인스턴스 선택을 재사용한다

- Status: Accepted
- Date: 2026-10-15
- Source: 사용자 요구(업데이트 후 대시보드에서 끝내지 않고 같은 인스턴스 클릭까지만 자동화, 지문 재인증 허용, 복잡한 세션 복구 제외), ADR-0174, ADR-0027, ADR-0149

## Context

PC 업데이트로 원격 연결이 끊기면 Android는 대시보드로 돌아가면서 선택한 PC를 지운다. 웹 Remote 소스는 PC가 제공하므로 PC가 내려간 동안 새 문서를 PC에서 받아 복구할 수 없다. Cloud 대시보드는 PC와 독립적으로 제공되고 이미 온라인 상태 갱신과 일반 연결 버튼을 소유한다. 사용자는 기존 세션을 유지하기보다 그 연결 버튼까지 자동으로 다시 실행하는 흐름을 선택했다.

## Decision

**재접속은 Cloud 대시보드로 돌아가 이전 인스턴스의 기존 연결 버튼을 한 번 실행한다.**

- 복귀 의도는 인스턴스 ID만 담는다. 이전 Remote 세션과 resume capability를 폐기하고 E2E 키를 새로 영속하거나 복구하지 않는다. Android는 설정된 지문 인증·페어링·새 보안 세션 연결 절차를 다시 거친다.
- Android의 기존 실패 후 대시보드 복귀는 선택한 ID를 URL fragment `reconnect=<id>`로 전달한다. 명시적 Exit·취소는 복귀 의도를 만들지 않는다. Cloud 문서가 준비되어 bridge가 허용된 후에만 자동 선택한다.
- 연결 의도가 살아 있는 웹 Cloud Remote의 일시적인 gateway 오류는 Cloud가 제공하는 `/remote/reconnect`로 이동한다. Cloud는 기존 relay 쿠키가 유효하고 여전히 소유한 인스턴스일 때만 그 ID를 대시보드 `#reconnect=<id>`로 전달한다. 쿠키가 없거나 만료·철회됐으면 일반 대시보드로만 돌아간다. 이 경로는 PC 파일이나 터널을 필요로 하지 않으며 권한을 발급하거나 갱신하지 않는다. 실제 재접속은 대시보드의 로그인·소유권 검증과 새 grant 발급을 거친다. 직접 접속의 재시도와 확정적인 제어권 거절은 기존 정책을 유지한다.
- 대시보드는 현재 로그인한 사용자의 목록에서 정확히 같은 ID만 선택한다. 오프라인이면 기존 목록 poll을 기다리고 온라인 버튼이 있을 때만 한 번 실행한다. 다른 PC로 대체하지 않고 실제 연결·소유권·정책 검증은 기존 서버·native 흐름이 수행한다.
- fragment는 웹에서 시작 시, Android에서 native 문서 READY 이후 소비한다. Android는 로드 완료까지 URL을 유지하여 native의 정확한 URL 일치 검증을 보존한다. 실행 전 메모리의 의도를 지운다. 사용자가 다른 연결·로그아웃을 선택하면 자동 선택을 취소한다. 실패·인증 취소 뒤 반복해서 클릭하지 않는다.
- Cloud 서버를 먼저 배포하고 이후 desktop/Android 클라이언트를 배포한다. 기존 클라이언트는 일반 연결을 계속 사용한다.

## Alternatives Considered

- E2E 세션·lease를 업데이트에 걸쳐 보존: 프로세스 수명·키·권한 복구 계약을 늘리며 사용자 요구에 필요하지 않다.
- PC 문서를 새로 받으며 대기: PC가 오프라인일 때 문서를 제공할 수 없다.
- 별도 재연결 화면·온라인 poll·연결 API 구현: 대시보드가 이미 같은 기능을 제공하므로 중복이다.

## Consequences

PC 재시작 동안에도 Cloud 화면에서 기다리고 기존 인증을 거쳐 복귀할 수 있다. 지문 인증이 다시 뜨며 Remote 문서의 임시 UI 상태는 새 연결 기준으로 복원된다. 웹과 앱은 동일한 대시보드 버튼 경로를 쓰며 연결 완료를 강제하지 않는다. 인스턴스 삭제·권한 상실·취소·다른 PC 선택·숨긴 탭·중복 목록 갱신에서 자동 선택이 잘못 실행되지 않는 회귀를 검증한다. 기존 자동 재접속의 끊긴 흐름을 고치지만 Cloud 복귀 endpoint와 대시보드 fragment 계약을 호환되게 추가하므로 ADR-0281에 따라 minor 변경이다.
