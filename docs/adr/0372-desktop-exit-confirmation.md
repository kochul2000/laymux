# 0372. PC 앱 종료 전에 기본 활성 확인을 받는다

- Status: Accepted
- Date: 2026-11-03
- Source: 사용자 요청(종료 확인·설정·다시 보지 않기), architecture/api-contracts.md §10·§15, ADR-0264·0279

## Context

PC 창 닫기는 곧바로 종료 준비와 터미널 정리를 시작한다. 실수로 창을 닫아 작업이 종료되는 것을 막으면서, 확인을 원하지 않는 사용자는 설정에서 해제할 수 있어야 한다. 업데이트 재시작과 준비 실패 후 손실 강행 확인은 별도 계약으로 유지한다.

## Decision

PC 앱의 명시적 창 닫기는 `exit.confirmBeforeExit`가 true일 때 종료 준비 전에 사용자 확인을 받는다.

- 설정의 단일 진실원은 기존 PC Settings이며 Rust·UI 기본값과 생략된 키의 기본값은 true다. Settings → 터미널 → 종료 시 동작에서 변경한다.
- 취소·Escape는 종료 예약, 입력 차단, checkpoint, Ctrl+C, PTY 종료를 시작하지 않는다. 중복 닫기는 기존 close handler의 단일 실행으로 합친다.
- 확인 창의 ‘다시 보지 않기’는 임시 상태다. 취소하면 폐기한다. 체크하고 종료를 확정하면 기존 설정 snapshot 저장·적용 경로로 `exit.confirmBeforeExit=false`를 먼저 저장한다. 저장 실패는 오류를 표시하고 확인 창을 유지한다. 설정 복구 쓰기 차단을 우회하지 않는다.
- 승인 후에만 기존 `begin_app_close` → 저장·터미널 정리 → 창 파괴 경로로 진입한다. 업데이트와 복구 재시작에는 이 확인을 추가하지 않는다.
- Windows·Linux PC에 동일하게 적용하며 Remote·Android에는 자체 종료 확인을 추가하지 않는다. dev 전용 lifecycle Automation에 실제 창 닫기 요청과 확인 창 조작을 추가하고 release 노출은 기존 금지를 유지한다.

## Alternatives Considered

- OS 기본 확인 창: 설정 해제 체크박스와 앱 내 다국어·자동화 검증을 일관되게 제공하기 어려워 선택하지 않는다.
- 체크 즉시 설정 변경: 취소해도 사용자 설정이 바뀌므로 선택하지 않는다.
- 종료 준비 후 확인: 취소하기 전에 터미널 작업을 중단할 수 있으므로 선택하지 않는다.

## Consequences

실수에 의한 종료를 예방하며 Settings와 확인 창의 선택이 같은 구성에 저장된다. 기본으로 한 번의 사용자 동작이 추가된다. 확인 UI는 앱 루트에서 유지하며 설정 저장 실패·취소·중복 요청·기본값·디스크 왕복·실제 창 닫기 경로를 테스트한다. UI 상태는 dev API와 스크린샷으로 검증한다. 사용자 요구로 기본값이나 업데이트 적용 범위를 바꾸면 새 ADR로 재검토한다.
