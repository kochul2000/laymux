# 0329. 데몬 재결합은 워크스페이스 표시 문맥을 메모리로 인계한다

- Status: Accepted
- Date: 2026-10-15
- Source: 사용자 요구(데몬 재결합 후 마지막 입력·상태 메시지·activity 및 최대화 상태 보존), [ADR-0194](0194-workspace-pane-last-input-second-line.md), [ADR-0301](0301-pty-daemon-default-adoption.md), [ADR-0319](0319-update-handoff-carries-terminal-title.md), [data-flow.md §8.23·§13](../architecture/data-flow.md)
- 관계: ADR-0194의 입력 보관 범위를 Zustand 단독에서 같은 사용자 GUI·PTY 데몬의 휘발성 메모리로 확장한다. 입력을 디스크에 저장하지 않는 원칙은 유지한다. ADR-0319의 기존 빌드 업데이트 title 인계는 유지한다.

## Context

PTY 데몬은 자식과 터미널 화면을 유지하지만 GUI의 마지막 제출 입력, 명령 결과와 에이전트 메시지는 유지하지 않는다. GUI가 재시작되면 기존 PTY에 재결합해도 워크스페이스 요약은 비어 있다. idle 에이전트는 새 출력을 내지 않아 자연 복구도 보장되지 않는다. 창 기하는 일반 종료에서만 저장하므로 종료 처리를 생략하는 업데이트에서는 최대화도 유실된다.

마지막 입력에는 민감 정보가 들어갈 수 있다. 이를 설정·SQLite·localStorage·handoff 파일에 저장하는 해결은 ADR-0194의 보안 제약을 위반한다. 한편 이전 작업 상태를 새 GUI의 권위 있는 관측으로 복원하면 진행 상태 순서·세대·권한 판단을 오염시킨다.

## Decision

**워크스페이스의 마지막 표시 문맥은 해당 PTY 데몬 세션의 메모리에만 보관하고, 같은 살아 있는 자식에 재결합할 때 복원한다. 작업의 현재 사실은 기존 실시간 관측으로 다시 판정한다.**

- GUI는 터미널별 마지막 제출 입력·입력 시각과 표시 원시 정보·마지막 작업 관측을 데몬에 갱신한다. 출력 바이트마다 저장하지 않고 변경된 문맥만 병합하며 업데이트 준비에서는 갱신 완료를 기다린다.
- 데몬은 문맥을 해석하지 않는 유한 크기 payload로 세션 메모리에 보관한다. 세션 종료와 함께 버리고 디스크·로그·일반 세션 목록에 싣지 않는다. 인증된 별도 제어 연결과 attach epoch로 갱신을 제한하여 이전 GUI가 새 소유자의 문맥을 덮어쓰지 못하게 한다.
- attach 응답의 선택적 metadata로 문맥을 인계한다. 비활성 workspace의 표시는 인증된 별도 읽기 요청으로 실제 살아 있는 세션·프로파일이 일치하는 문맥만 먼저 읽으며, PTY를 attach하거나 workspace를 마운트하지 않는다. 한 응답은 최대 2개 문맥, 문맥 하나는 최대 64 KiB다. 새 PTY·다른 프로파일·다른 세션에는 적용하지 않는다. 확장을 모르는 이전 데몬은 별도 제어 연결만 거절하며 기존 터미널 연결과 작업은 유지한다. 디스크 대체 저장은 하지 않는다.
- 복원한 입력·메시지는 더 최신 입력·OSC 사실을 덮어쓰지 않는다. 이전 작업 관측은 표시용 이력이며 stale로 취급한다. clear 허용·sleep 억제·종료·세션 귀속·알림 재발행에는 쓰지 않는다. 새 실시간 관측은 이력을 대체한다.
- 창 크기·위치·최대화는 기존 창 기하 저장소를 사용한다. move/resize 변화 때 저장하고 업데이트 준비에서 중복 수집하지 않는다. 최소화 시에는 마지막 정상 기하를 유지한다. 사용자 터미널을 종료하거나 명령을 주입하지 않는다.

## Alternatives Considered

- **입력까지 세션 DB에 저장:** 프로세스 수명 밖으로 민감 입력을 남겨 기각한다.
- **출력 화면을 재파싱해 복구:** 출력에서 제출 입력을 추측할 수 없고, redraw에 없는 완료 메시지도 유실된다.
- **현재 작업 상태를 그대로 복원:** 오래된 상태를 새 권위로 취급해 안전 관련 판단과 알림이 잘못될 수 있다.
- **업데이트 파일에만 표시 정보 추가:** 일반 GUI 재결합을 해결하지 못하고 입력을 디스크에 남긴다.

## Consequences

GUI만 재시작하면 작업 화면과 표시 문맥이 함께 이어진다. 데몬까지 종료되면 입력 이력은 사라지는 것이 의도된 동작이다. 이전 빌드 데몬은 확장을 지원하지 않으므로 그 세션의 문맥 인계는 보장하지 않는다. 프로토콜 확장의 이전 빌드 공존, epoch 경쟁, 크기 제한, 최신 관측 우선, 디스크 비저장 및 실제 dev 재결합을 검증한다.

표시용 보관은 입력 앞부분 2048 code point, 기타 문자열 앞부분 512 code point로 제한하며 문맥 전체를 64 KiB로 제한한다. 이는 입력 전송이나 현재 GUI의 전체 입력을 자르는 제한이 아니다. 큰 문맥 때문에 출력·재결합 제어가 막히는 것을 방지한다.

창 최대화 누락 수정은 patch지만, 입력 문맥을 GUI 수명 밖에서도 휘발성으로 유지하는 호환 기능 추가가 포함되므로 누적 버전 영향은 minor다(ADR-0281). 표시 이력을 현재 작업의 권위로 사용하려면 별도 ADR이 필요하다.
