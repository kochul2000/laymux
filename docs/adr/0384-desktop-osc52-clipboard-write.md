# 0384. Windows 터미널의 OSC 52 클립보드 쓰기는 사용자가 허용한다

- Status: Accepted
- Date: 2026-11-19
- Source: Claude Code 백그라운드 화면의 복사 실패 재현, [ADR-0001](0001-osc-rust-single-pass.md), [data-flow §8.3](../architecture/data-flow.md#83-osc-처리-파이프라인)

## Context

Claude Code의 전체 화면에서 선택한 텍스트는 Claude가 관리한다. dev에서 `←`로 에이전트 목록에 들어가 드래그 후 `Ctrl+C`를 누르면 PTY에 OSC 52가 도착했으나 Windows 클립보드는 바뀌지 않았다. OSC 52는 터미널 프로그램이 시스템 클립보드를 바꿀 수 있는 계약이다. 같은 출력은 GUI 재결합과 렌더러 복원에도 나타날 수 있으므로, 요청이 들어오는 경로와 실행을 허용하는 범위를 정해야 한다.

## Decision

**Windows 데스크톱은 사용자가 허용한 경우 현재 키보드 포커스를 가진 터미널의 실시간 OSC 52 텍스트 쓰기를 처리한다.**

- `terminal.allowOsc52ClipboardWrite`의 기본값은 `false`다. Windows 터미널 설정에서 사용자가 켜면 적용한다. WebView는 실제 xterm 입력 포커스를 가진 세션 ID와 generation을 Rust에 전달한다. Rust는 해당 포커스가 유지되고 메인 창이 Windows 전경에 있을 때만 쓰기를 수행한다. 창이 전경을 잃거나 메인 페이지가 새로 로드되면 Rust에서 권한을 회수한다.
- Rust PTY 콜백의 OSC 단일 패스가 요청을 해석한다. 시퀀스가 여러 청크에 걸칠 수 있으며, 시퀀스 전체가 실시간 출력에 속하고 PTY 콜백 입구부터 실제 쓰기까지 포커스 권한이 유지되어야 한다. 데몬에서 가져온 누락 출력, 렌더러의 스냅샷 및 재생, 이전 generation에는 클립보드 부작용을 적용하지 않는다.
- 대상으로 `c`, 종료자로 BEL과 ST를 받는다. 최대 64 KiB의 디코딩된 UTF-8 텍스트를 기존 Windows 쓰기 함수에 전달한다. 내용이 비어 있거나 NUL을 포함하는 요청, 손상된 입력, 읽기 질의 및 다른 대상은 무시한다. 클립보드 처리 로그에는 내용을 담지 않는다. 별도로 활성화한 PTY 원시 출력 추적은 일반 PTY 바이트와 같이 인코딩된 요청 일부를 기록할 수 있다.
- 터미널의 기존 선택 복사 단축키와 입력 전달을 유지한다. 이 기능의 쓰기 대상은 Windows 데스크톱 클립보드다.

## Alternatives Considered

- 일반 드래그를 xterm 선택으로 강제하면 Claude의 마우스 선택과 상호작용이 바뀐다.
- xterm 클립보드 애드온에 위임하면 렌더러가 쓰기 권한을 가지며 실시간 요청과 출력 재생을 분리해야 한다. Rust의 기존 OSC 처리 위치에서 구분할 수 있다.
- 모든 터미널 출력에 쓰기를 허용하면 사용자가 보고 있지 않은 pane의 프로그램도 클립보드를 바꿀 수 있다.

## Consequences

- Claude Code 및 같은 제어 시퀀스를 보내는 터미널 프로그램을 사용할 수 있다. 허용 상태에서는 포커스된 프로그램이 키 입력 없이도 클립보드를 쓸 수 있으므로 설정에서 이 동작을 알린다.
- Linux 지원에는 네이티브 클립보드 쓰기 구현이 필요하다.
- 청크 경계, 잘못된 입력, 포커스 전환과 출력 재생의 권한을 테스트하고 dev에서 실제 Claude 화면과 Windows 클립보드를 검증한다.
