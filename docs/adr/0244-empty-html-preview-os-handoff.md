# 0244. 빈 HTML 미리보기는 본문에서 PC 연결 프로그램 열기를 안내한다

- Status: Proposed
- Date: 2026-09-08
- Source: 사용자 제공 `dd.preview.html`의 SPA fallback과 브라우저 버튼 요구, PR #1039, [data-flow.md §8](../architecture/data-flow.md), [ADR-0193](0193-viewer-os-handoff-buttons.md)
- Extends: ADR-0193 Decision 4의 본문 CTA 대상을 바이너리에서 빈 HTML 미리보기까지 확장한다.

## Context

JavaScript로만 본문을 만드는 HTML은 내장 sanitizer가 스크립트를 제거하면 빈 컨테이너만 남는다. 빈 화면의 이유와 다음 행동을 알려야 하며, 안내 문구만으로는 파일을 브라우저로 여는 행동까지 연결되지 않는다. 크기만 지정된 컨테이너도 있어 DOM 박스의 존재만으로 내용을 판단할 수 없다.

Remote iframe은 빈 sandbox로 격리돼 부모가 렌더 크기를 읽을 수 없다. 이 안내를 위해 격리를 완화하거나 실행용 파일 서버를 만드는 것은 범위 밖이다. 로딩 문구만 남는 SPA를 확정 판별하는 것도 비목표다.

## Decision

**공유 HTML renderer가 sanitizer 이후 표시 가능성을 판정하고, 빈 HTML의 데스크톱 본문에는 기존 PC 연결 프로그램 열기 CTA를 표시한다.**

- 판정은 정리된 DOM과 인라인 CSS를 사용한다. 빈 컨테이너와 명시적으로 숨긴 콘텐츠를 제외하고 텍스트·이미지·컨트롤·CSS 장식 단서를 보존한다. 픽셀이나 실제 렌더 크기를 측정했다고 간주하지 않는다.
- 판정 결과와 안전한 문서는 같은 함수에서 만든다. 데스크톱은 빈 결과를 React 안내와 `OsHandoffActions`로 표시하고, 원문 Source 전환을 유지한다. 원본 파일 경로를 기존 `open_in_os`에 전달하며 브라우저를 강제 선택하지 않는다. HTML의 PC 연결 프로그램이 브라우저이면 브라우저가 열린다.
- 클릭·확인·실패 표시·호스트 경로 변환은 ADR-0193의 기존 소유자를 재사용한다. 자동 실행하지 않는다.
- Remote는 같은 판정에 따른 문서 안내와 기존 Download 버튼을 유지한다. 호스트 프로그램 실행 권한이나 새 API 필드를 추가하지 않는다.

## Alternatives Considered

- 구조적 빈 문자열 검사만 사용: 크기만 있는 컨테이너와 숨겨진 텍스트를 충분히 구분하지 못한다.
- iframe 렌더 크기 또는 픽셀 비교: 빈 컨테이너도 크기가 있고 Remote sandbox의 DOM 접근은 차단된다. 별도 측정 iframe·캡처 파이프라인의 비용과 보안 표면이 이번 안내보다 크다.
- 안내 문구만 표시: 사용자가 제공한 파일에서 브라우저 열기 버튼이 보여야 한다는 수용 조건을 충족하지 않는다.
- 전용 브라우저 실행 경로: OS 연결 프로그램 정책과 WSL 경로 변환·확인 로직을 중복하므로 기각한다.

## Consequences

- 빈 SPA에서 다음 행동이 본문에 보이고, 정상 정적 문서와 로딩 문구는 유지된다.
- 보수적 휴리스틱이므로 클리핑·가림·동일한 배경색 등 모든 빈 화면을 잡지는 못한다. 오판이 확인되면 사례 기반으로 재검토한다.
- 제공 파일은 로컬에서 실제 바이트로 확인하고, 저장소에는 데이터 없는 최소 구조로 회귀 테스트를 둔다. DOM 판정·Remote payload·실제 desktop CTA와 클릭·확인 취소·Source 전환을 검증한다.
