# 0377. 스택 전환 줄의 +는 가장 오른쪽에 레이어를 추가한다

- Status: Accepted
- Date: 2026-11-09
- Source: 사용자 요구(스택의 `+`로 만든 창을 가장 오른쪽에 추가), [data-flow.md §스택](../architecture/data-flow.md#스택), [ADR-0297](0297-pane-stack-slot-layer-model.md)
- 정정: ADR-0297의 쌓기 위치 규칙 중 전환 줄 `+`의 삽입 위치만 정정한다.

## Context

스택 전환 줄의 `+`는 탭 목록 끝에 있지만 활성 레이어 바로 뒤에 새 레이어를 삽입한다. 중간 탭에서 누르면 새 탭이 오른쪽 끝이 아닌 중간에 생긴다. 사용자는 이 버튼이 항상 가장 오른쪽에 창을 추가하기를 요청했다.

삽입 위치를 바꾸더라도 새 터미널은 사용자가 보고 있던 레이어의 프로필·CWD를 상속하고, 기존 터미널 세션은 유지해야 한다. 컨트롤 바·단축키·Automation·Remote의 쌓기 의미는 이번 결정의 범위 밖이다.

## Decision

**스택 전환 줄의 `+`는 활성 탭 위치와 관계없이 슬롯 레이어 목록 끝에 새 레이어를 삽입하고 표시·포커스한다.**

- 레이어 순서의 단일 진실원은 기존 `workspace-store`의 `layers`이다. 컴포넌트는 삽입 인덱스를 전달하고 기존 순수 삽입 함수가 상태를 한 번에 갱신한다.
- 삽입 위치와 상속 원본은 독립이다. 프로필·CWD는 누르기 전 활성 레이어에서 기존 정책대로 상속한다.
- 컨트롤 바 Stack·`pane.stack`·Automation·Remote는 활성 레이어 뒤 삽입을 유지한다. Automation의 기존 표시·포커스 보존 계약도 유지한다.
- 새 설정·영속 스키마·외부 API는 추가하지 않는다. Windows·Linux에서 같은 UI 경로를 사용한다.

## Alternatives Considered

- 활성 레이어 뒤 삽입 유지: 목록 끝에 있는 `+`의 위치와 생성 위치가 어긋나 사용자 요구를 충족하지 못한다.
- 모든 쌓기를 끝 삽입으로 변경: 이번 요청과 무관한 단축키·Automation·Remote의 기존 계약까지 바꾸므로 기각한다.
- 생성 후 끝으로 이동: 중간 순서를 store 구독자에게 노출하고 추가 상태 전환이 필요하므로 기존 삽입 함수의 인덱스 옵션을 사용한다.

## Consequences

- 어느 탭에서 눌러도 새 탭이 가장 오른쪽에 나타나고 즉시 선택된다.
- 같은 쌓기 기능이라도 전환 줄 `+`와 다른 진입점의 삽입 위치가 다르므로 living doc과 회귀 테스트에 구분을 남긴다.
- 첫째·중간·마지막 탭에서의 클릭, 활성 원본 프로필·CWD 상속, 포커스, 기존 세션 유지를 컴포넌트 통합 테스트로 검증한다.
- 다른 쌓기 진입점도 끝 삽입으로 통일하라는 요구가 생기면 해당 외부 계약을 포함해 별도로 재검토한다.
