# 0374. MCP 연결 서버 실패는 데스크톱에서 알리고 서버만 재시도한다

- Status: Proposed
- Date: 2026-11-03
- Source: 사용자 요구(Windows·WSL MCP 접속 실패 시 알림과 서버 재시작), architecture/api-contracts.md §12.2, ADR-0002

## Context

MCP 서버의 시작 실패와 실행 중 오류는 로그에만 남고 앱은 계속 동작했다. 사용자는 연결 시간 초과만 보고 앱 전체를 다시 시작해야 했다. MCP, Automation API, Remote는 같은 고정 포트의 HTTP 리스너를 공유하므로 MCP만 별도 포트로 옮기지 않고 복구할 경계가 필요하다. 앱과 PTY, 에이전트 프로세스의 재시작은 범위에서 제외한다.

## Decision

공유 HTTP 서버의 실패를 데스크톱에 지속 표시하고, 네이티브 IPC로 실패한 서버만 다시 시작한다.

- AppState의 서버 조정기가 starting/running/failed 상태, 오류, 단조 증가 revision과 실행 핸들을 소유한다. 기존 별도 automation_port 상태를 대체한다.
- 최초 시작과 사용자 재시도는 같은 비동기 게이트로 직렬화한다. 정상 서버에는 재시도가 멱등이며, 자동 무한 재시도는 하지 않는다.
- bind 실패와 serve task의 오류·panic·취소를 failed로 기록한다. 사용자 알림은 HTTP 서버에 의존하지 않는 Tauri IPC 조회를 사용하므로 초기 시작 실패도 놓치지 않는다.
- 재시도는 기존 빌드의 고정 포트·IP allowlist·Remote 인증 계약을 유지한다. 공유 서버 전체를 복구하며 앱·PTY·에이전트를 종료하지 않는다. 복구 후 에이전트 재연결이 필요할 수 있음을 안내한다.
- MCP 리소스 이벤트 브리지는 앱 수명 동안 한 번만 설치한다. 발견 파일은 bind 성공 이후 게시하고, 서버 종료 시 현재 PID 소유 파일만 제거한다. 타 인스턴스 파일은 변경하지 않는다.
- dev 전용 실패 주입 API로 실제 서버 중단 → 네이티브 알림 → 버튼 재시도 → HTTP/MCP 복구를 검증한다. release에서는 주입을 거절한다.

## Alternatives Considered

- 앱 전체 재시작: 진행 중인 터미널·에이전트에 불필요한 영향을 주므로 선택하지 않는다.
- MCP 전용 포트 분리: 등록 URL·인증 표면·서버 수명 관리가 늘어나므로 이번 복구 범위에 포함하지 않는다.
- 로그만 남기거나 HTTP health만 조회: 서버 시작 자체가 실패했을 때 사용자에게 복구 경로를 제공하지 못한다.
- 자동 무한 재시도: 포트 점유·권한 오류가 지속될 때 반복 실패를 감추므로 명시적 재시도를 선택한다.

## Consequences

앱과 터미널을 유지하면서 연결 서버를 복구할 수 있고 OS 오류를 사용자에게 전달한다. 상태 조회용 IPC와 UI 주기 조회 비용이 추가된다. 서버가 중단되면 진행 중인 HTTP/MCP/Remote 연결은 끊기며 클라이언트 재연결이 필요하다. 서버 task가 살아 있는 상태의 부분적인 MCP 프로토콜 정지나 클라이언트 설정 오류는 이번 실패 판정 범위 밖이며 별도 진단이 필요하다. 테스트는 임시 포트·발견 디렉터리를 사용한다.
