# 0244. 스프레드시트는 범위 선택과 스크롤 창으로 탐색한다

- Status: Accepted
- Date: 2026-09-08
- Source: 사용자 UX 피드백, ADR-0242, architecture/data-flow.md 데스크톱 스프레드시트 뷰어
- 관계: ADR-0242의 페이지 탐색과 복사 인터랙션을 정정한다. 파일 읽기 계약과 상한은 유지한다.

## Context

복사 버튼 두 개와 설명 없는 페이지 번호는 일반 스프레드시트의 조작 방식과 다르다.
사용자는 행·열 머리글 선택, 셀 드래그 선택, 복사 단축키와 연속 스크롤을 요구했다.
최대 10,000행을 한 번에 DOM으로 만들면 렌더링 비용이 커진다.

## Decision

**React의 선택 범위를 원본 데이터에서 복사하고, 세로 스크롤 위치에 해당하는 행만 렌더링한다.**

- 선택은 현재 필터 결과의 시작·끝 행/열과 종류(셀·행·열)를 소유한다. DOM의 텍스트 선택에 의존하지 않는다.
- 머리글 클릭·드래그는 행 또는 열 전체를, 셀 드래그는 직사각형을 선택한다. Shift 클릭은 같은 종류의 범위를 확장한다.
- 화면 밖의 선택 데이터도 TSV에 포함한다. 검색 또는 시트 변경은 선택을 초기화한다.
- 복사는 표에 포커스된 브라우저 기본 `copy` 이벤트에서 `text/plain`으로 제공한다. 별도 단축키 하드코딩이나 복사 IPC를 추가하지 않는다.
- 행 높이 28px·열 너비 144px를 고정하고 보이는 행·열과 여유 영역만 렌더링한다. 작은 시트는 창 너비로 늘리지 않는다. 긴 셀은 한 줄로 자르고 전체 값은 툴팁과 복사로 제공한다.
- 드래그 중 가장자리에서 자동 스크롤한다. 페이지 버튼과 페이지 번호는 제거한다.
- Rust 읽기 상한과 시트 단위 파싱은 유지하되 표시 상한을 처음 초과하면 셀 순회를 중단한다. 잘린 응답의 totalRows/totalColumns는 전체 크기가 아니라 중단 시점까지 관측한 좌표의 최대치다. 이번 창 처리는 DOM 렌더링 범위이며 파일을 청크로 다시 읽지 않는다.

## Alternatives Considered

- 모든 행 렌더링: 구현은 짧지만 상한까지의 DOM 비용이 크다.
- 그리드 라이브러리: 편집·서식 기능이 필요 없고 기존 표와 브라우저 복사 이벤트로 요구를 충족한다.
- 네이티브 텍스트 선택: 직사각형·행·열 선택 및 가상화된 화면 밖 복사를 표현하지 못한다.

## Consequences

기존 스프레드시트와 비슷한 조작을 제공하고 DOM 행 수를 화면 크기에 제한한다.
고정 행 높이 때문에 여러 줄 셀은 표 안에서 모두 보이지 않는다. 표시 상한 이후에 있는 셀은 검색·복사하지 않는다. ZIP 안전 검사·공유 문자열 읽기와 calamine의 XLS/ODS 선행 파싱 비용은 남지만 기존 원본·압축 해제·ODS 확장 상한을 유지한다.
범위 선택·필터 초기화·화면 밖 TSV 복사·실제 스크롤과 단축키를 테스트한다.
