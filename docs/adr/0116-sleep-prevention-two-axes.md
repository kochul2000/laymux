# 0116. 절전 방지는 수동 스위치와 자동 정책 두 축이고 상단 바 버튼은 수동 축만 표시한다

- Status: Proposed
- Date: 2026-08-02
- Source: issue #733, [ADR-0114](0114-sleep-prevention-mode.md) 정정, architecture/api-contracts.md §10
- Amends: [ADR-0114](0114-sleep-prevention-mode.md) 의 "모드 값은 `off | always | whenBusy` 세 가지이고 상단 바 버튼이 셋을 순환한다" 부분. 억제를 거는 계층(Rust 단일 소유자·watchdog·desired/held 분리·플랫폼 전략)과 파생 지점이 하나라는 결정은 그대로 유효하다.

## Context

ADR-0114 는 절전 방지를 `off | always | whenBusy` 3값 모드 하나로 모델링하고, 상단 바 버튼이 그 셋을 순환하게 했다. 실사용에서 `whenBusy` 가 `off` 처럼 읽힌다는 보고가 나왔다(issue #733).

원인은 채널 과부하다. 버튼 하나가 서로 독립인 두 축을 색·opacity·점 세 채널에 섞어 담았다.

| 상태 | 색 | opacity | 추가 마크 |
|---|---|---|---|
| `off` | text-secondary | 0.35 | — |
| `whenBusy` + idle | text-secondary | 0.65 | r=1.7px 점 |
| `whenBusy` + busy | accent | 1 | 점 |
| `always` | accent | 1 | — |

opacity 가 "모드가 off" 와 "지금 억제 안 함" 두 의미를 겸했다. 그 결과 `off` 와 `whenBusy(idle)` 의 차이가 opacity 0.35↔0.65 와 14px 안의 1.7px 점뿐이 되어, 둘 다 흐린 회색으로 보인다. ADR-0114 는 "모드와 실제 억제 상태가 다를 수 있다는 사실이 UI 에 노출돼야 한다"고 적었지만, 그 노출을 모드 축과 같은 채널에 얹은 것이 실패의 원인이었다.

부차적으로 3상태 순환은 어포던스가 없다. 아이콘만으로 다음 클릭 결과를 알 수 없고, `always` 에서 `off` 로 가려면 두 번 눌러야 한다.

제약과 force:

- **두 축은 수명이 다르다.** "지금 이 작업 동안 재우지 마"는 하루에도 몇 번 뒤집는 순간적 override 다. "터미널이 돌면 재우지 마"는 한 번 정하고 잊는 정책이다. 자주 누르는 컨트롤의 순환 안에 거의 안 바꾸는 정책을 끼워 넣으면 매번 그것을 지나쳐야 한다.
- **아이콘 면적은 14px 이다.** 상단 바 아이콘이 실제로 구분해줄 수 있는 상태는 두어 개다. 여섯 개를 넣으면 어느 것도 안 읽힌다.
- **억제 실패는 여전히 보여야 한다.** ADR-0114 의 판단은 유효하다 — 실패를 감추면 UI 가 지켜준다고 말하는 동안 머신이 잠든다.
- 마이그레이션은 하지 않는다(내부 개발 단계, AGENTS.md).

범위: 사용자에게 노출되는 컨트롤의 모양과 설정 스키마의 모양. 비목표: OS 억제 구현, busy 판정 방식, 화면 절전, 워크스페이스별 정책.

## Decision

**절전 방지는 서로 독립인 boolean 두 개(`power.keepAwake`, `power.keepAwakeWhenBusy`)로 소유하고, 상단 바 버튼은 `keepAwake` 하나만 토글하고 하나만 표시한다. 자동 정책은 Settings 에만 둔다.**

- **설정 스키마는 3값 문자열 하나를 boolean 두 개로 교체한다.** `power.sleepPrevention` 은 제거한다. `keepAwake` 는 수동 스위치, `keepAwakeWhenBusy` 는 자동 정책이며 둘 다 기본값 `false` 다. 열거값 검증이 사라지고 타입이 검증을 대신한다.
- **억제 판정은 두 축의 OR 이다.** `shouldInhibitSleep({keepAwake, keepAwakeWhenBusy}, hasWorkingTerminal)` 이 여전히 유일한 파생 지점이다(ADR-0005). 두 축이 독립이므로 OR 이 정의 그 자체다 — 어느 쪽이든 재우지 말라고 하면 재우지 않는다.
- **상단 바 버튼은 `keepAwake` 의 표시 겸 토글이다.** 클릭은 `keepAwake` 만 뒤집는다. 아이콘은 `keepAwake=false` 면 달, `true` 면 사선 그은 달 두 상태뿐이다. `whenBusy` 를 뜻하던 점 마크는 제거한다.
- **버튼은 백엔드의 `held` 를 그리지 않는다.** ADR-0114 는 버튼이 실제 억제 상태를 그리게 했지만, 그러면 자동 정책이 걸어 놓은 억제 때문에 버튼이 사용자가 누르지도 않은 상태를 보여주고, 눌러도 그림이 안 바뀌는 순간이 생긴다. 축 분리의 요점은 버튼이 자기 축만 말하는 것이다.
- **자동 정책은 아이콘에 나타나지 않는다.** 자동을 켜 둔 사용자가 idle 일 때 머신이 자는 것은 그가 요청한 동작이므로 경고할 것이 없다. 정책 상태는 Settings 와 tooltip 문장이 갖는다.
- **실패만은 축 분리의 예외다.** 억제 요청이 실패하면 원인이 수동이든 자동이든 버튼이 경고색과 tooltip 사유를 올린다. 실패는 축 위의 값이 아니라 고장이고, 이것을 감추면 `systemd-inhibit` 이 없는 머신에서 자동 정책이 영원히 조용히 실패한다. `useSleepInhibitStore` 는 남지만 버튼이 읽는 것은 `failed` 뿐이다 — `active` 는 coordinator 의 상태 조정용으로만 남는다.
- **tooltip 이 축 두 개를 문장으로 말한다.** 아이콘이 못 담는 것(자동 정책이 켜져 있는지, 지금 왜 깨어 있는지)은 hover 텍스트가 담는다.

## Alternatives Considered

- **3모드를 유지하고 시각 채널만 분리(모양=모드, 색=지금).** diff 가 파일 하나 5줄이다. 기각: `off`/`whenBusy(idle)` 는 구분되지만 3상태 순환의 어포던스 문제와 수명이 다른 두 결정을 한 컨트롤에 묶은 문제가 남는다. 증상만 가린다.
- **점 마크를 키워서 자동 정책 켜짐을 아이콘에 계속 표시.** 정보가 더 많다. 기각: 14px 아이콘에 두 축을 다시 넣는 것이고, 사용자가 그 정보로 할 행동이 없다. 자동 정책의 idle 침묵은 놀라움이 아니다.
- **버튼이 백엔드 `held` 를 그리고 클릭은 `keepAwake` 를 토글.** "지금 깨어 있는가"라는 가장 궁금한 사실을 보여준다. 기각: 표시 축과 조작 축이 어긋난다. 자동 정책이 억제 중일 때 버튼을 눌러도 그림이 그대로여서 클릭이 먹지 않은 것처럼 보인다.
- **`keepAwake` 를 localStorage 같은 로컬 UI 상태로.** 기각: ADR-0114 와 같은 이유로 앱 동작을 바꾸는 사용자 구성이며 재시작 후에도 유지돼야 한다.
- **문자열 모드를 유지한 채 `whenBusy` 만 별도 boolean 추가(`always|off` + 플래그).** 마이그레이션이 필요 없다. 기각: 두 표현이 겹쳐 `off` + 자동 켜짐 같은 조합의 의미가 모호해진다. 내부 개발 단계라 마이그레이션 회피는 force 가 아니다.

## Consequences

- 아이콘이 두 상태뿐이라 상단 바에서 즉시 읽힌다. 대신 아이콘만으로는 자동 정책 여부를 알 수 없고, 그것을 알려면 tooltip 이나 Settings 를 봐야 한다 — 의도한 교환이다.
- 설정 필드가 하나에서 둘로 늘고 열거값 검증(`SLEEP_PREVENTION_MODES`)이 사라진다. `semantic_validation` 의 해당 항목과 Rust 상수를 함께 제거한다.
- 기존 `settings.json` 의 `power.sleepPrevention` 값은 파일 로드 시 무시된다. `whenBusy` 를 쓰던 사용자는 Settings 에서 한 번 다시 켜야 한다. MCP `update_settings` 로 옛 키를 보내면 `unknown_key` 로 거절된다 — 에이전트에게는 침묵보다 거절이 낫다.
- 버튼이 `held` 를 안 읽으므로, 자동 정책만으로 억제 중일 때 UI 에 "지금 깨어 있음"을 말해주는 표시가 없다. 요구가 생기면 tooltip 이나 별도 위젯으로 확장한다 — 버튼 아이콘에 되돌리지 않는다.
- 재검토 조건: 축이 셋 이상으로 늘거나(워크스페이스별 정책, 시간대 정책), "지금 억제 중"을 항상 보이게 해달라는 요구가 생기는 경우.
