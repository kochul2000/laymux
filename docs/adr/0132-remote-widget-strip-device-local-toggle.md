# 0132. 원격 위젯 스트립의 표시는 호스트 게이트와 기기-로컬 토글의 논리곱이다

- Status: Accepted
- Date: 2026-08-04
- Source: 사용자 요구("리모트에서 위젯바에 대한 토글이 메뉴 안에 있으면 좋겠다"); [ADR-0124](0124-remote-widget-strip-mirrors-desktop.md), [ADR-0004](0004-settings-vs-ui-state-separation.md), [ADR-0129](0129-remote-chrome-row-rebases-fit-baseline.md); `docs/architecture/api-contracts.md` §13 Remote UI API
- Extends: [ADR-0124](0124-remote-widget-strip-mirrors-desktop.md) — "원격 표시 자체의 on/off 는 `settings.remote.widgets` 하나가 갖는다"는 문장을 **표면 존재 게이트를 두 개로** 정정한다. 배치 SoT 가 데스크톱이라는 결정은 그대로다.

## Context

[ADR-0124](0124-remote-widget-strip-mirrors-desktop.md) 는 원격 스트립을 켜고 끄는 수단을 호스트 설정 `settings.remote.widgets` 하나로 두었다. 그 게이트의 근거는 "세로 픽셀이 희소한 기기에서 스트립을 통째로 포기할 수단"이었는데, 정작 그 판단은 **기기마다 다르다**. 스트립은 원격 크롬 한 줄이고 그만큼 터미널 행을 깎는다([ADR-0129](0129-remote-chrome-row-rebases-fit-baseline.md)) — 27인치 모니터의 브라우저 탭에서는 공짜에 가깝고 휴대폰 세로 화면에서는 비싸다.

현재 계약에서는 휴대폰에서 한 줄을 되찾으려면 호스트 설정을 꺼야 하고, 그러면 같은 토큰으로 붙어 있는 태블릿·PC 브라우저에서도 스트립이 사라진다. 반대로 태블릿을 위해 켜 두면 휴대폰은 계속 한 줄을 잃는다. 하나뿐인 게이트가 전역이라 기기별 요구를 표현할 수 없다.

또 하나의 force 는 그 게이트가 **호스트에 있다**는 점이다. 원격에서 호스트 설정을 바꾸는 경로를 여는 것은 열람 표면이 구성 표면이 되는 일이고, 지금 위젯 라우트는 lease 없이 응답하는 열람 전용 라우트다([ADR-0124](0124-remote-widget-strip-mirrors-desktop.md)). 브라우저 하나의 화면 취향 때문에 그 경계를 무르게 할 이유는 없다.

제약과 force:

- `settings.json` 은 사용자가 의도적으로 편집·공유하는 구성만 담고, 표면 로컬 UI 상태는 담지 않는다([ADR-0004](0004-settings-vs-ui-state-separation.md)). "이 브라우저에서 스트립을 접어 둔다"는 기기 상태이지 공유할 구성이 아니다.
- 원격 표면은 이미 기기-로컬 선택을 localStorage 에 두는 선례가 있다 — 입력 모드, 키셋 배열, 컴포저 recall 토글과 그 범위([ADR-0055](0055-composer-history-scope-setting.md)).
- 게이트를 클라이언트로 옮기는 것이 아니라 **추가**하는 것이다. 호스트가 껐으면 클라이언트가 무엇을 하든 값이 오지 않아야 한다는 [ADR-0124](0124-remote-widget-strip-mirrors-desktop.md) 의 "게이트 판정은 서버가 하며 클라이언트의 선의에 맡기지 않는다"는 유지된다.
- 스트립이 사라지면 폴은 그릴 대상이 없다. 끈 기기가 5초마다 브리지를 두드리는 것은 [ADR-0124](0124-remote-widget-strip-mirrors-desktop.md) 가 idle 주기를 늘려 줄이려던 비용을 그대로 되살린다.

범위는 원격 클라이언트의 표시 게이트 하나와 그 토글이 놓일 자리다. 비목표: 원격에서 호스트 설정 변경, 원격 전용 배치·옵션, 위젯 종류별 개별 토글, 데스크톱 표면의 변경.

## Decision

**원격 스트립이 보이는 조건은 `settings.remote.widgets`(호스트, 전역) AND 기기-로컬 토글(브라우저별, 기본 켬)이다. 두 게이트는 소유자가 다르고 서로를 덮어쓰지 않는다.**

### 게이트 소유

- 호스트 게이트는 그대로 [ADR-0124](0124-remote-widget-strip-mirrors-desktop.md) 의 것이다. 서버가 판정하고, 꺼져 있으면 위젯 없는 응답을 돌려준다. 기기 토글이 켜져 있어도 되살리는 경로는 없다.
- 기기 게이트는 **그 브라우저의 것**이다. localStorage 에 사는 표면-로컬 상태이며 호스트에 전송되지 않고 다른 클라이언트에 영향을 주지 않는다. 같은 토큰의 다른 기기는 각자의 값을 갖는다.
- 기기 게이트는 **표시 여부만** 바꾼다. 배치도, 위젯 종류도, 데스크톱의 어떤 상태도 건드리지 않는다 — 끈 상태로 접속을 유지하다 다시 켜면 데스크톱이 그리고 있는 그대로가 돌아온다.
- 기본값은 켬이다. 명시적으로 끈 브라우저만 꺼진 상태로 남는다. 저장이 불가능한 환경(프라이빗 모드 등)은 켬으로 동작한다 — 읽기 실패가 기능을 없애지 않는다.

### 표면

- 토글은 **내비게이션 드로어의 `Display` 섹션**에 산다. 드로어는 원격의 유일한 상시 메뉴이고, 스트립을 끈 사용자에게도 남아 있는 표면이다.
- 키바 ⚙ 팝오버(기존 "Remote surface's settings home")에는 두지 않는다. 팝오버는 keyBar 가 보일 때만 열리는 종속 표면이라, 스트립을 되살리는 스위치를 그 뒤에 두면 복구 경로가 다른 크롬의 가시성에 의존하게 된다.
- 토글은 연결 상태와 무관하게 조작 가능하다(`locked` 대상이 아니다). 기기 취향은 lease 도 토큰도 요구하지 않으며, 접속 전에 미리 꺼 둘 수 있어야 첫 화면부터 행을 지킨다.

### 폴링과 레이아웃

- 기기 게이트가 꺼지면 위젯 폴은 **멈춘다**. [ADR-0124](0124-remote-widget-strip-mirrors-desktop.md) 의 "그릴 항목이 없어도 폴을 멈추지 않는다"는 규칙은 배치가 데스크톱에서 늘어난 것을 알아차릴 표면이 폴뿐이라는 근거였는데, 사용자가 스스로 표면을 접은 경우에는 알아차릴 대상 자체가 없다. 다시 켜는 사건이 폴을 되살린다.
- 폴 재개 여부는 세션이 폴을 원하는지(연결됨)와 기기가 허용하는지의 논리곱으로 판정한다. 토글은 세션 상태를 만들지 않고, 연결은 기기 취향을 덮지 않는다.
- 토글로 스트립이 사라지거나 나타나는 것은 데스크톱 배치 변화로 그렇게 되는 것과 같은 사건이다 — fit 기준선 재산정은 [ADR-0129](0129-remote-chrome-row-rebases-fit-baseline.md) 의 기존 경로를 그대로 탄다. 크롬 변화의 원인마다 다른 레이아웃 경로를 만들지 않는다.

## Alternatives Considered

- **원격에서 `settings.remote.widgets` 를 끄게 한다.** 게이트가 하나로 유지되고 설명이 짧다. 그러나 전역이라 기기별 요구를 표현하지 못하고(원 요구가 정확히 그것이다), 열람 전용 라우트뿐이던 원격 위젯 경로에 호스트 설정 쓰기를 추가하게 된다.
- **호스트가 기기별 선호를 저장한다(클라이언트 이름·토큰별 맵).** 기기를 바꿔도 따라오지만, `settings.json` 이 사용자 구성만 담는다는 [ADR-0004](0004-settings-vs-ui-state-separation.md) 를 깨고, 클라이언트 식별자가 안정적이지 않은데 그것을 키로 삼는 상태가 호스트에 쌓인다.
- **토글을 키바 ⚙ 팝오버에 둔다.** 기존 원격 설정과 한자리에 모인다. 그러나 keyBar 가 숨겨진 상태에서는 열 수 없어, 접은 표면을 되살리는 스위치가 또 다른 크롬의 가시성에 종속된다.
- **스트립 자체에 닫기(×) 버튼.** 조작이 가장 가깝지만 꺼진 뒤 되살릴 표면이 사라진다. 그리고 좁은 폭에서 위젯과 자리를 다툰다.
- **끈 뒤에도 폴을 계속한다.** [ADR-0124](0124-remote-widget-strip-mirrors-desktop.md) 의 문구와 형식적으로 일치하지만, 아무도 보지 않는 값을 위해 클라이언트마다 상시 브리지 요청이 남는다. 그 규칙의 근거(배치 변화 감지)는 표면을 스스로 접은 기기에 적용되지 않는다.
- **CSS 로만 숨긴다(`display: none`).** 구현이 한 줄이다. 그러나 폴은 계속 돌고, 숨긴 높이가 fit 계산에 남을지 여부가 [ADR-0129](0129-remote-chrome-row-rebases-fit-baseline.md) 경로와 별개 규칙이 되어 행 수 회복이 보장되지 않는다.

## Consequences

- 원격 스트립의 표시 조건이 두 개가 된다. "원격에 위젯이 안 보인다"는 신고는 호스트 설정과 그 기기의 토글 두 곳을 확인해야 한다 — 진단 표면이 하나 늘어난다.
- 기기-로컬 상태가 localStorage 에 하나 추가된다. 브라우저 데이터를 지우면 기본값(켬)으로 돌아간다. 이는 원격의 다른 기기-로컬 선택들과 같은 성질이며 마이그레이션 대상이 아니다.
- 끈 기기는 위젯 브리지 요청을 전혀 만들지 않는다. 호스트 게이트를 끄지 않고도 폴 비용이 0 이 되는 경로가 처음 생긴다.
- 드로어에 `Display` 섹션이 생긴다. 이후 원격의 기기-로컬 표시 선택(크롬 표시 여부 류)은 이 섹션이 자리가 된다 — 팝오버와 드로어에 표시 설정이 반씩 흩어지지 않게, 새 표시 토글은 여기에 모은다.
- 후속 문서 작업: `api-contracts.md` §13 에 표시 조건이 두 게이트의 논리곱임을 적는다. `/remote/v1/widgets` 의 응답 계약은 바뀌지 않는다.
- 재검토 조건: 기기 선호가 브라우저를 넘어 따라와야 한다는 요구가 생기면 호스트 저장을 다시 검토한다. 표시 토글이 여럿으로 늘어 드로어 섹션이 설정 화면처럼 커지면 원격 설정 표면의 통합을 새 결정으로 다룬다.
