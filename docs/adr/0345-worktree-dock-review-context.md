# 0345. 워크트리 검토 맥락은 조회 대상에 귀속하고 화면 크기에 맞춰 목록과 상세를 배치한다

- Status: Accepted
- Date: 2026-10-19
- Source: 사용자 요청(dock 실사용 평가의 정당한 불편 수정), ADR-0343, ADR-0344, architecture/api-contracts.md §15
- 관계: ADR-0343의 CWD 수신·검사 정책을 유지하며 UI 생명주기와 갱신 표시를 구체화한다.

## Context

PC의 Worktrees는 좁은 dock에 다른 도구와 함께 놓인다. 기본 240px·3분할에서는 네 줄 목록과 인라인 상세가 작업 영역을 소모하고 필터·닫기가 스크롤 밖으로 사라진다. 같은 저장소를 유지하도록 CWD 수신을 꺼도 workspace 기준 재마운트 때문에 검토 상태가 사라졌다. 새 터미널을 직접 생성한 뒤에도 이전 제거 후보가 남았다.

리모트 모바일도 상세가 전체 목록 아래에 붙고 파일 뷰어를 닫으면 검토 화면을 잃었다. 검토 상태를 보존하되 실제 조회 경로·실행 환경이 바뀌면 이전 제거 확인을 폐기해야 한다. Git 전체를 주기적으로 재검사하거나 별도 저장소 핀·영속 상태를 추가하지 않고 기존 사용 관측과 CWD 소유권을 유지한다. 범위는 PC dock과 리모트의 검토 흐름이며 Git diff, 강제 제거, 제거 보호 정책 변경은 포함하지 않는다.

## Decision

**검토 UI는 같은 조회 대상에서 유지하고, 좁은 dock은 목록/상세 전환, 넓은 영역은 두 영역 병렬 배치를 사용하며 오래된 검사를 현재 제거 가능 상태로 표시하지 않는다.**

- 선택·필터·스크롤은 마운트된 뷰의 일시 상태로 유지한다. workspace ID만으로 Worktrees를 재마운트하지 않는다. CWD 수신이 꺼지면 마지막 경로와 발신 환경을 유지하고, 켜진 상태의 그룹 전환은 새 그룹의 현재 CWD 또는 빈 대상으로 전환한다.
- 실제 CWD·발신 terminal·명시적 초기 대상이 바뀌면 이전 상세와 제거 확인을 폐기한다. 새 그룹에 터미널이 없을 때 이전 그룹 저장소를 현재 대상으로 표시하지 않는다.
- 필터와 저장소·수신 상태는 본문 스크롤 밖에 둔다. 상세의 식별/닫기·주요 동작·제거 확인 버튼은 별도 고정 영역으로 두고 내용만 스크롤한다. 목록은 폴더 말단과 핵심 상태 중심으로 축약하되 보존 사유를 숨기지 않는다.
- 수동 갱신 중 같은 대상의 이전 목록과 선택은 유지하지만 제거 적격성과 후보 수는 검사 중 상태로 바꾼다. 새 결과를 받기 전 이전 검사로 제거 확인을 재사용하지 않는다.
- 도구가 새 터미널을 생성하면 즉시 해당 경로의 제거 표시를 보류한다. 기존 terminal store의 실제 세션 준비 관측 뒤 다시 검사한다. 생성 의도는 UI 갱신 신호이며 실제 사용 정보의 SoT나 backend 제거 정책을 대체하지 않는다.
- 리모트도 목록과 상세를 전환하고 목록 복귀 위치를 유지한다. 워크트리에서 연 파일 뷰어의 사용자 닫기는 같은 lease·terminal·CWD의 상세로 복귀한다. 다른 도구 열기·세션 상실·대상 변경은 이 복귀 맥락을 폐기하고 이전 제거 확인을 되살리지 않는다. 이 일시 상태는 현재 리모트 문서의 메모리에만 둔다.
- 설정 스키마·영속 override·Automation/MCP/Remote 계약은 바꾸지 않는다. Git 검사 동시성 제한과 backend 실행 직전 재검증을 유지한다.

## Alternatives Considered

- dock 폭을 넓히기: 240→320px에서도 행 높이와 상세의 세로 비용이 크게 줄지 않아 사용자 배치를 해결책으로 요구하지 않는다.
- 모든 검토 상태 영속화: 임시 선택과 제거 확인을 복원 데이터로 만들 필요가 없어 채택하지 않는다.
- workspace 전환마다 초기화: 대상 유지 설정과 dock의 지속 사용 맥락을 깨뜨리므로 실제 대상 변경에만 초기화를 결합한다.
- 전체 Git 주기 폴링: ignored 파일이 많은 저장소와 WSL의 실행 비용이 커 도구의 명시적 동작과 관측된 준비 상태에 갱신을 결합한다.

## Consequences

작은 dock에서 항목 식별과 상세 작업이 쉬워지고 터미널 확인 뒤 검토를 이어갈 수 있다. 목록과 상세의 전환·스크롤 복귀 및 갱신 중 표시를 함께 검증해야 한다. 이전 목록은 갱신 중 참고 정보로만 남으며 오래된 적격성은 사용할 수 없다. 생성 실패·지연은 보수적으로 표시하고 사용자가 수동 갱신할 수 있게 한다.

TDD로 그룹 전환·늦은 응답·생성 전후 적격성·검토 상태를 검증하고 dev의 240/320px·3분할·하단 dock에서 다시 사용한다. 기존 기능의 오류와 사용 흐름 수정이므로 이 변경의 버전 영향은 patch이며 누적 워크트리 기능 릴리스는 minor다.
