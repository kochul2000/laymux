# 0358. 작업 상태는 진입·60초 재확인으로 복구하고 Codex live 제목과 유일한 기록을 대조한다

- Status: Proposed
- Date: 2026-10-27
- Source: Remote에서 대기 Codex가 점·stateUnknown으로 남아 clear할 수 없다는 사용자 제보 및 workspace/pane 진입·1분 이상 폴백 요구, [data-flow.md §9](../architecture/data-flow.md), [ADR-0248](0248-codex-turn-lifecycle-activity.md), [ADR-0321](0321-agent-session-record-fills-unconfirmed-task.md)
- Amends: ADR-0248의 작업 상태에 허용하는 귀속 증거. 저장 복원점의 귀속 계약은 유지한다.

## Context

작업 상태는 GUI 메모리에 있고 Remote는 호스트의 계산 결과를 표시한다. 업데이트로 GUI가 다시 시작하면 이전 작업과 훅 레지스트리가 사라진다. Codex 프로세스가 살아 있어도 프로세스 로그가 현재 대화 선택을 확정하지 못하면 턴 조회는 미확인이다. 현재 대화를 live 제목과 훅으로 확인한 경우에도 선택 키가 없는 복원 전용 결과는 턴 조회에서 제외된다. 재조회만 반복해도 같은 증거 제한 때문에 상태를 복구하지 못한다.

제목의 Ready나 조용한 출력은 유휴의 증거가 아니다. 현재 세대의 관리된 OSC 제목 식별자와 그 프로세스 환경 안의 유일한 최상위 rollout을 대조할 수는 있다. 또 title로 확정된 Claude는 기록 폴링을 멈추므로 진입과 긴 주기의 명시적 재확인 경로가 필요하다.

## Decision

**호스트는 workspace·pane 진입과 60초 주기에 기존 상태 관측기를 다시 실행하고, Codex는 현재 live 제목 식별자와 유일한 최상위 기록으로 턴 상태를 복구할 수 있다.**

- 작업·훅·출력의 원시 상태와 단일 표시 계산 함수는 유지한다. Remote는 별도 작업 상태를 영속하지 않는다.
- pane 포커스·같은 pane 재선택, workspace 전환·재선택, PTY 준비, 문서 foreground 복귀는 대상 상태의 즉시 재조회를 요청한다. 60초마다 숨김·비활성 pane을 포함해 재확인한다.
- 공통 요청은 기존 Codex 턴·Claude/Grok 기록·선택된 훅 구독자로 전달한다. 대기 타이머를 앞당기고, 진행 중 조회가 있으면 완료 뒤 한 번 더 읽는다. 요청을 겹치거나 정상 관측의 세대·입력·앱·sequence 보호를 해제하지 않는다.
- Claude/Grok의 명시적 재확인은 title로 확정된 대상도 기록을 읽는다. 읽는 동안 새 title·입력이 오면 새 관측을 보존한다. 모달 대기는 기존 검출기가 계속 소유한다.
- Codex의 기존 프로세스 선택이 우선한다. 선택 키가 없을 때만 현재 PTY 세대의 live 관리 제목 UUID/축약 UUID를 실제 프로세스의 Codex 홈 안에서 유일한 최상위 rollout 헤더와 대조한다. 훅 메모리나 resume 요청이 없어도 이 증거를 사용할 수 있다. 감지 설정이 heuristic이어도 현재 관리 제목이 있으면 같은 검증을 적용한다.
- 제목 문구에서 작업 상태를 추론하지 않는다. 실제 running·종료·결과는 기존 rollout reader만 판정한다. 복원용 ID만 있고 live 제목이 없거나 파일 누락·손상·중복·축약 충돌·보조 스레드이면 상태를 합성하지 않는다.
- 프로세스 선택의 단순 증거 부재와 명시적 차단을 구분한다. 미완료 thread 전환·종료된 loop·복수 최상위 후보·검증 거부를 관측했으면 이전 live 제목이 남아 있어도 제목 복구를 금지한다. ADR-0258·0267의 전환/거부 시 과거 대화로 fallback하지 않는 불변식을 유지한다.
- 제목 기반 선택 키는 backend가 `title:<generation>:<revision>`으로 발급한다. session ID는 별도 scope 구성 요소다. 파일 I/O 전후 제목 revision·PTY 세대를 검사해 ABA와 교체를 거부한다. 기존 중복 대화 귀속 거부도 유지한다.
- 이 증거 확장은 턴 표시 조회에만 적용한다. 일반/종료 checkpoint의 복원점 결정에는 적용하지 않는다. API 응답 스키마·인증·포트·입력 계약은 바꾸지 않는다. 상태 조회는 PTY 입력·resize·interrupt를 보내지 않는다.

## Alternatives Considered

- 미확인을 유휴로 처리: 작업·대화상자 중 clear를 허용하므로 기각한다.
- 이전 GUI 작업 상태를 디스크에서 복원: GUI가 없는 동안 진행한 작업을 잘못 표시할 수 있다. 현재 증거를 다시 읽는다.
- Remote에 별도 상태 저장·폴러 추가: PC와 clear 정책이 달라지고 호스트의 귀속 실패를 해결하지 못한다.
- 타이틀 재출력을 위해 focus·resize·입력 주입: 재출력을 보장하지 않으며 사용자 작업을 방해한다.
- 1초마다 모든 title 확정 상태 재조회: 진입 시 즉시성과 장기 자가복구는 60초 재확인으로 확보하고 기존 유휴 조회 비용을 유지한다.

## Consequences

업데이트 뒤 훅 메모리를 잃어도 살아 있는 관리 제목·기록이 있으면 Codex 작업과 clear 정책을 다시 확정한다. PC와 Remote가 같은 복구 결과를 사용한다. 진입 시 대상 기록 조회와 60초 전체 재확인의 I/O 비용이 추가된다. 관리 제목 자체가 없거나 CLI 내부 기록 형식이 바뀌면 미확인 보호가 유지된다.

테스트는 훅 메모리 없는 재부착, 제목 충돌·ABA·세대 교체·파일 중복·보조 스레드, 진입·60초 sweep·dispose, 진행 중 요청 합치기와 늦은 응답 거부를 검증한다. 현재 프로세스의 공식 상태 구독이 가능해지면 이 파일 기반 폴백을 재검토한다.
