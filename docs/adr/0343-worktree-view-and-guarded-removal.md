# 0343. 워크트리 뷰는 Git 상태와 laymux 사용 정보를 함께 보여주고 재검증 후 개별 제거한다

- Status: Proposed
- Date: 2026-10-18
- Source: 사용자 요청(워크트리 목록·정리 및 dev 실기 검증), architecture/overview.md §6·§7, architecture/api-contracts.md §12·§14·§15, ADR-0003, ADR-0297, ADR-0306

## Context

여러 에이전트가 만든 워크트리를 정리하려면 Git 상태와 해당 폴더를 쓰는 laymux 터미널을 함께 알아야 한다. 에이전트는 이미 Git 명령으로 조사·정리를 수행할 수 있으므로 같은 동작의 전용 MCP를 추가할 이유는 없다. 반면 사용자는 목록을 보고 작업으로 돌아가거나 개별 제거할 수 있어야 한다.

워크스페이스는 워크트리와 일대일 관계가 아니다. 숨은 워크스페이스·스택 레이어·복원 대기 터미널과 분리된 PTY도 고려해야 한다. Git의 clean 판정만으로 ignored 로컬 파일까지 보존된다고 가정할 수 없다. Windows 드라이브와 WSL 배포판은 경로 및 Git 실행 환경도 다르다.

초기 dev 검토에서 별도 저장소 핀이 기존 pane의 컨트롤바 핀과 같은 아이콘으로 표시되어 의미를 혼동시켰다. 대상 경로를 따라갈지 유지할지는 기존 CWD 수신 설정이 이미 제어하므로 별도의 저장소 고정 상태를 만들지 않는다.

## Decision

독립 `WorktreeView`에서 Git 워크트리 목록과 laymux 사용 정보를 합성하고, 명시적으로 확인한 개별 워크트리만 실행 직전 재검증 후 제거한다.

- 목록·HEAD·브랜치·파일 상태의 진실원은 해당 실행 환경의 Git이다. laymux는 별도의 워크트리 등록부를 소유하지 않는다. 공용 Git 디렉터리와 실행 환경으로 저장소를 구분하며 GitHub `owner/repo`로 합치지 않는다.
- 뷰는 기존 pane의 CWD 수신 설정으로 SyncGroup CWD를 따른다. 수신을 끄면 마지막 대상을 유지한다. 명시적인 `view.repositoryPath`는 마운트 초기 경로로만 사용하며 이후 CWD 수신을 차단하지 않는다. 별도 저장소 핀이나 고정 경로 override는 두지 않는다. 행 선택은 상세 조회이며 CWD를 전파하지 않는다. 작업으로 이동하거나 새 터미널을 여는 동작은 명시적 UI 조작이다.
- CWD를 따르는 조회는 전파 원본 터미널 ID로 실행 환경을 결합한다. backend는 원본의 현재 CWD를 확인하고 Windows의 WSL 경로를 해당 배포판의 UNC로 확정한다. 이후 검사·제거는 그 경로를 사용하며 기본 배포판을 추측하지 않는다. SSH 원격 CWD를 로컬 경로로 취급하지 않는다.
- 사용 정보는 live terminal registry, 저장된 모든 workspace layer·dock, PTY daemon inventory를 결합한다. 동일 terminal의 live 상태가 저장된 CWD보다 우선하고 live CWD를 모르면 과거 저장 경로로 대체하지 않는다. 경로는 디렉터리 경계를 지켜 비교하고 Windows 드라이브 별칭과 WSL 배포판을 구별한다.
- 사용 경로는 해당 실행 환경에서 심볼릭 링크를 해석한다. WSL은 동일 배포판에서 시간·출력 제한을 적용한 `readlink -f`를 사용하고 경로를 확인할 수 없으면 제거를 허용하지 않는다.
- 관측할 수 없는 daemon의 사용 여부를 미사용으로 간주하지 않는다. 목록은 경고와 함께 제공하고 사용 정보가 불완전하면 제거를 거부한다. 앱 밖 프로세스 사용 여부까지 완전히 안다고 주장하지 않는다.
- live registry에 없는 daemon 세션은 저장된 pane에 연결되더라도 저장 CWD를 현재 CWD로 단정하지 않는다. 저장 경로는 `daemon` 사용 정보로 표시하지만 관측은 불완전하다. 표시 전용 daemon display context는 제거 판단에 재사용하지 않는다.
- daemon inventory의 `Ending`은 종료 요청과 종료 완료를 구별하지 않으므로 미사용의 근거로 쓰지 않는다. 해당 세션이 남아 있으면 사용 관측 불완전으로 제거를 차단한다.
- 후보는 검사가 성공하고 제거 차단 사유가 없는 항목이다. 미검사·조회 실패를 clean으로 표시하지 않는다. main/bare·잠금·경로 누락·detached HEAD·서브모듈·assume-unchanged/skip-worktree 인덱스 플래그·변경/미추적/ignored 파일·현재 경로·사용 중 또는 복원 참조가 있는 대상은 차단한다. upstream과 ahead/behind는 참고 정보이며 원격 fetch·PR 조회를 자동 수행하지 않는다. 병합 여부와 로컬 커밋의 보존 필요성은 사용자가 별도로 판단한다.
- 제거 요청은 조회할 저장소, 목록에 속한 정확한 절대 경로, 확인한 HEAD를 포함한다. 제거 직전 Git 상태와 laymux 사용 정보를 다시 검사하고 일반 `git worktree remove`를 실행한다. 강제 제거·브랜치 삭제·prune·일괄 삭제는 제공하지 않는다.
- Git 2.34처럼 NUL 구분 워크트리 목록을 지원하지 않는 환경은 해당 옵션 미지원이 확인된 경우에만 줄 구분 porcelain으로 조회한다. 그 형식에서 모호한 개행 경로는 조회 실패로 처리하며 정리 후보로 추측하지 않는다.
- 앱 내부 제거 요청은 직렬화한다. 재검증과 Git 실행 사이에 파일 변경, 터미널 CWD 이동 또는 새 PTY 생성이 일어나는 경쟁을 완전히 원자적으로 막는 계약은 아니다. Git 자체의 제거 검증을 유지하고 성공 후 목록을 다시 조회한다.
- Rust 공통 서비스 위에 Tauri command와 기존 IP allowlist를 따르는 Automation API를 제공한다. Automation은 목록·검사·제거와 뷰의 상세/필터 조작을 지원한다. 별도의 워크트리 관리 MCP는 추가하지 않는다. 기존 터미널/워크스페이스 조회 MCP도 계속 사용할 수 있다.

## Alternatives Considered

- GitHubView에 탭 추가: GitHub 없는 저장소도 관리해야 하며 로컬 clone의 신원이 원격 저장소와 달라 독립 뷰를 선택한다.
- 전용 관리 MCP: 기존 에이전트의 Git 실행과 중복되므로 채택하지 않는다. laymux 고유 정보는 공통 조회 결과에 포함한다.
- clean이면 즉시 삭제: ignored 파일, hidden terminal, 복원 및 daemon 상태를 놓칠 수 있어 명시적인 상세 확인과 재검증을 채택한다.
- 모든 워크트리를 workspace로 등록: 기존 자유 레이아웃과 다중 터미널 관계를 제한하므로 도입하지 않는다.
- 별도 저장소 핀: 기존 pane 핀과 다른 의미를 같은 도상으로 표현하고 CWD 수신 설정과 기능이 중복되어 채택하지 않는다.

## Consequences

사용자는 작업 상태와 제거 불가 이유를 한 화면에서 확인한다. GitHub 연결 없이 사용할 수 있고 Git 작업은 셸 도구를 쓰는 에이전트와 공유된다. 보수적인 제거 정책 때문에 빌드 산출물 같은 ignored 파일이 있는 워크트리는 외부 Git 작업으로 정리해야 한다.

Git 검사에는 프로세스 비용이 있으므로 UI 검사의 동시성을 제한한다. 오래된 비동기 응답은 현재 저장소·선택 상태에 적용하지 않는다. 새로운 view 설정과 Automation 계약은 living doc에 기록한다. 테스트는 임시 Git 저장소로 보존·제거를 확인하고 dev에서 실제 UI·API·스크린샷을 검증한다. 기능 추가이므로 버전 영향은 minor이며 이번 검토에서 버전 발행은 수행하지 않는다.

daemon이 원래 CWD를 정확히 제공하거나 사용자가 강제/일괄 정리를 요구하면 보호 범위와 권한을 새 ADR에서 다시 결정한다.
