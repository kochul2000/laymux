# 0359. 에이전트 재판정은 관측 실패를 종료로 발행하지 않는다

- Status: Accepted
- Date: 2026-10-27
- Source: v3.4.1에서 Windows·WSL Codex/Claude activity와 작업 상태가 다시 미확인으로 내려간다는 사용자 제보, `v3-ai-0` 두 pane의 정상→shell 스냅샷, [data-flow.md §9](../architecture/data-flow.md), [ADR-0009](0009-process-tree-interactive-app-liveness.md), [ADR-0135](0135-activity-reconcile-backend-diff-push.md), [ADR-0358](0358-agent-task-state-entry-and-periodic-recovery.md)
- Amends: ADR-0135의 양방향 재판정에서 에이전트 종료를 발행할 수 있는 증거 조건.

## Context

호스트는 3초마다 activity를 재판정하고 60초마다 전체 결과를 다시 발행한다. 작업 상태의 진입·60초 재조회는 이 워커와 독립적이다. 프로세스 관측이 일시적으로 `Unknown`이거나 `Ambiguous`이고 최근 출력에 식별 신호가 없으면 기존 detector는 shell로 열화한다. 재판정 워커는 이 값을 실제 종료와 구분하지 않고 발행하며 종료 정리도 실행한다. Codex의 현재 제목 식별자가 함께 지워지므로, 프로세스를 다시 찾더라도 조용한 앱이 새 제목을 보내기 전에는 ADR-0358의 대화·턴 복구 증거까지 사라진다.

출력이 없는 재부착에서도 별도 문제가 있다. 출력 버퍼가 없거나 비어 있으면 detector가 생존 프로세스를 묻기 전에 반환하므로, 프로세스가 확인된 앱도 shell로 보일 수 있다. 프로세스 식별과 작업의 진행·종료 상태는 다른 관측이다. 작업을 조회할 수 없다는 이유로 앱을 종료시키거나, 앱이 살아 있다는 이유로 작업을 유휴로 만들 수 없다.

범위는 지원 에이전트(Claude·Codex·Grok)의 activity 재판정과 그에 따른 종료 정리다. 주기 단축·제거, 새 상태 영속, 제목 문구로 작업 상태 추론, 프로세스 관측 실패를 종료로 사용하는 것은 비목표다.

## Decision

**프로세스가 확인한 앱은 출력 유무보다 우선하며, 재판정은 프로세스 관측 실패만으로 이미 식별한 에이전트의 종료를 발행하지 않는다.**

- native·WSL 공통 detector는 프로세스의 `Running(app)`을 먼저 적용한다. 버퍼가 없거나 비어 있어도 같은 판정을 사용하고, 남은 다른 앱의 제목보다 우선한다. control 경로의 ring·registry 건강성 검사와 세대 보호는 유지한다.
- 재판정 후보가 직전 지원 에이전트를 잃었을 때 `Unknown`·`Ambiguous` 또는 같은 앱의 `Running`은 종료 증거가 아니다. 해당 pane은 직전 diff 기준만 유지하고 이번 발행·종료 정리에서 제외한다. 60초 전체 재발행도 예외가 아니다. 오래된 값을 새 관측으로 재발행하지 않는다.
- `NoneAlive`와 확인된 다른 프로세스의 handover는 기존 종료 정리를 계속 실행한다. 미확인 중 보존한 기준으로 이후의 실제 종료도 감지한다. 삭제된 pane은 보존하지 않으며, PTY 세대가 바뀌면 기존 세대 기준을 폐기한다.
- 미확인 패스는 Codex live 제목과 Claude 작업 문맥을 종료 정리로 지우지 않는다. task 관측·훅 lease·선택 키·입력·세대·sequence의 기존 유효성 검사는 완화하지 않는다. 앱 라벨 보존은 유휴·성공·clear 허용의 증거가 아니다.
- 이 보존은 재판정의 내부 diff 기준이다. API·설정·네트워크 계약과 Remote의 호스트 상태 표시 원칙은 유지한다. 다른 TUI의 기존 휴리스틱은 이 에이전트 전용 보존에 포함하지 않는다.

## Alternatives Considered

- 60초 작업 재조회 또는 activity 재발행 제거: 정상 상태를 잃는 종료 오판을 남기고, 재부착·진입 복구와 frontend drift 수렴까지 없애므로 기각한다.
- 관측 실패 때 이전 값을 무조건 다시 발행: 오래된 앱 식별을 새 증거처럼 보이게 하고 최신 이벤트와 경쟁하므로 기각한다. 발행을 보류하고 diff 기준만 남긴다.
- WSL 양성 캐시의 수명 연장: 실패와 종료를 구분하지 않는 소비자 문제를 남기며 native에도 적용되지 않는다.
- 미확인 작업을 유휴로 처리: 진행 중 작업에 clear를 허용할 수 있으므로 기각한다.

## Consequences

일시적 관측 실패가 앱 라벨·대화 식별자·작업 복구를 연달아 무너뜨리지 않는다. 출력 없는 재부착과 앱 전환도 프로세스 증거를 동일하게 사용한다. 다만 프로세스 관측이 계속 실패하면 마지막 앱 라벨이 남을 수 있다. 이때 작업 상태의 stale/unknown 보호는 계속 적용되며, 실제 종료의 수렴은 다음 정상 관측에 의존한다.

테스트는 빈 버퍼·경쟁 제목, 미확인 및 모호한 관측에서의 전체 재발행, 뒤이은 확인된 종료·handover, 삭제·세대 교체를 검증한다. 읽기 전용 WSL 부하 재현은 단순 poll 횟수와 함께 liveness도 기록한다. dev 통합 검증은 격리한 Windows·WSL 프로세스의 실제 PTY·OSC·기록, 80초 guest 관측 실패, Remote 표시, GUI 재기동 후 무출력 65초와 확인된 종료를 측정한다([재현 기록](../agent-activity-regression-repro-2026-10-27.md)). 제보의 타이머 인과관계는 별도 런타임 증거로 판단하며, 이 결정만으로 모든 관측 실패의 발생 원인이 해결됐다고 주장하지 않는다.
