# 0389. 회수와 겹치는 터미널의 pane 생성만 기다린다

- Status: Proposed
- Date: 2026-11-24
- Source: 회수 중 리뷰 pane 생성에 관한 사용자 요구, [ADR-0231](0231-hidden-eviction-target-scoped-input-admission.md), [ADR-0365](0365-navigation-admission-during-hidden-eviction.md), [ADR-0388](0388-pane-creation-waits-for-hidden-eviction.md)
- 관계: ADR-0388의 회수 대기 범위를 대체하고, ADR-0231의 대상별 승인을 개별 터미널 생성과 자동화 입력까지 확장한다.

## Context

회수는 숨김 터미널의 대화 복원 정보와 PTY를 보호한다. 현재 pane 생성과 뒷단의 PTY 생성·자동화 입력은 다른 터미널을 회수할 때도 멈춘다. 회수 대상 저장의 안정성 검사는 해당 터미널에 한정되며, 레이아웃 저장기는 전체 스냅샷을 직렬로 저장하고 수집 이후 생긴 변경을 후속 저장한다.

## Decision

**자동화 분할·스택 추가와 단일 PTY 작업은 회수 대상과 실제로 겹칠 때만 회수에 의해 제한된다.**

분할·스택은 프런트엔드가 해석한 원본 슬롯의 모든 터미널 ID를 승인 범위로 사용한다. 슬롯과 소속 터미널은 변경 직전에 다시 확인한다. 대기 중 구성이 바뀌면 원래 슬롯을 기준으로 승인 범위를 다시 확인한다. Rust는 승인된 요청의 범위를 프런트엔드 응답까지 추적한다. 동시에 시작되는 회수는 겹치는 요청이 응답할 때까지 기다린다.

회수 중인 원본 슬롯의 승인 대기 상한은 10초다. 대상 확인 및 실행에 쓰는 기존 프런트엔드 응답 예산은 합계 5초다. 전달 전 취소, 창 닫기 확정 및 전역 종료는 생성 요청을 중단시킨다. PTY 생성, 입력 준비, 단일 터미널 MCP·REST 입력은 해당 터미널 ID로 승인받는다. 회수는 대상 PTY를 저장한 뒤 닫고 다중 대상을 변경하는 작업과 앱 전체 종료에는 기존의 차단과 drain을 적용한다.

회수 저장 중 레이아웃이 바뀌면 체크포인트의 기존 변경 번호 검사와 후속 저장을 사용한다. 분할과 스택 추가도 저장을 요청한다. 체크포인트 저장 형식은 유지한다.

## Alternatives Considered

- 전역 대기를 유지하면 회수의 지연이 다른 리뷰 터미널에 그대로 전파된다.
- pane 이벤트만 먼저 전달하면 PTY 시작과 첫 입력이 여전히 회수를 기다린다.
- 워크스페이스 전체를 잠그면 같은 워크스페이스의 서로 다른 슬롯까지 차단한다.

## Consequences

다른 슬롯의 리뷰 pane은 회수 중에도 만들고 사용할 수 있다. 대상 확인을 위해 내부 읽기 요청이 한 번 추가된다. 회수와 동시에 실행되는 분할·스택, 대기 중 바뀐 슬롯, 만료·취소, 첫 입력 및 후속 스냅샷을 검증한다.
