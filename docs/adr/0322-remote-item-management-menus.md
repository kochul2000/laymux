# 0322. Remote 워크스페이스와 페인은 관리 메뉴·스킵 두 버튼을 제공한다

- Status: Accepted
- Date: 2026-10-14
- Source: 사용자 요구(워크스페이스·페인 모두 `⋯`·스킵, 숨기기·닫기는 메뉴 안, 워크스페이스 롱클릭 즉시 이름 변경), [api-contracts.md §13.3](../architecture/api-contracts.md), [ADR-0297](0297-pane-stack-slot-layer-model.md), [ADR-0320](0320-remote-drawer-skip-visibility-columns.md)
- Supersedes: ADR-0320의 직접 숨김 열 배치. 기존 스킵 상태·visibility 계약은 유지한다.

## Context

Remote 목록에 스킵·숨김·닫기를 직접 나열하면 조작부가 복잡해진다. 사용자는 워크스페이스와 페인 행 모두 `⋯`·스킵 두 버튼으로 통일하고, 숨기기·닫기는 워크스페이스처럼 관리 메뉴를 띄워 실행하기로 했다. 닫기는 PC 방식 두 번 활성화만 사용하고 설명·추가 확인창을 표시하지 않는다. 워크스페이스 이름 변경은 롱클릭으로 바로 입력할 수 있어야 한다. Remote에는 닫기 API가 없으므로 콘텐츠 수명과 제어권 경계를 명시한다.

## Decision

Remote의 워크스페이스와 페인 행은 `⋯` 관리 메뉴·스킵 순서로 배치하고, 숨기기·닫기는 각 대상의 관리 메뉴에서 실행한다.

- 페인 메뉴는 워크스페이스 메뉴와 같은 native dialog 형태로 대상 이름과 숨기기/복원·닫기를 표시한다. 기존 워크스페이스 이름 변경·템플릿 저장도 유지한다. 숨겨진 비터미널 페인도 자신의 관리 메뉴에서 복원할 수 있다.
- 닫기 버튼은 기본색으로 시작한다. 첫 활성화만 위험 색상·테두리로 강조하고, 같은 대상을 두 번째 활성화하면 실행한다. 별도 설명·확인창은 없다. blur·마우스/펜 pointerleave·Escape·다른 컨트롤 클릭·메뉴 재열기·대상/제어권 변경은 해제한다. 터치 pointerleave와 같은 대상의 navigation 갱신은 확인 상태를 유지한다.
- 헤더에는 현재 페인의 기존 선택형 스킵만 제목 바로 옆에 둔다. 목록의 스킵은 비현재 페인과 워크스페이스에도 계속 제공한다. 상태 SoT는 기존 기기 localStorage다.
- 워크스페이스 행의 버튼 아닌 영역을 450ms 누르면 전환 없이 기존 관리 dialog의 이름 변경 폼으로 바로 진입한다. 8px 초과 이동·pointerup/cancel/leave는 대기를 취소한다. 버튼 클릭·스크롤은 이름 변경을 시작하지 않으며 롱클릭 이후 click은 워크스페이스 전환을 실행하지 않는다.
- `POST /remote/v1/panes/{id}/close`, `POST /remote/v1/workspaces/{id}/close`는 기존 bearer/IP/Origin gate와 활성 controller lease를 요구한다. Android E2E 내부 HTTP에도 같은 정확한 POST 경로만 허용한다. 성공 시 workspace-state-changed를 발행한다.
- 페인 `id`는 슬롯 인덱스가 아니라 콘텐츠 레이어 ID다. 실행 시 frontend가 현재 소유자를 조회하고 기존 workspace/dock store가 삭제·정리를 소유한다. 스택에서는 지목한 레이어 하나만 닫는다. 마지막 workspace 슬롯의 마지막 레이어·마지막 dock pane·마지막 workspace는 닫지 않는다. 없는 ID나 반복 삭제는 다른 대상으로 대체하지 않는다.
- 비활성 대상 닫기는 활성 workspace와 Remote 출력 선택을 유지한다. 활성 대상이 사라지면 기존 포커스 전환 소유자와 Remote navigation 갱신으로 남은 터미널에 착지한다. 실패 시 메뉴·선택을 보존하고 확인 상태를 해제한다. dock에는 숨기기를 제공하지 않는다.

## Alternatives Considered

- 헤더 숨김·닫기: 현재 대상에만 조작을 제한하고 목록 문맥에서 관리할 수 없다.
- 목록 편집 모드·별도 관리 목록: 단일 대상 관리에 추가 단계가 필요하다.
- 직접 숨기기·닫기 열: 사용자가 선택한 두 버튼 체계와 충돌한다.
- 워크스페이스 메뉴로 페인까지 관리: 대상 범위가 섞인다.
- 인덱스로 닫기: navigation 갱신·재배치 중 대상이 바뀔 수 있다.

## Consequences

두 대상의 관리 위치가 통일되고 비현재 대상도 선택 전환 없이 관리할 수 있다. 숨김·닫기는 메뉴를 여는 탭이 추가되며, 롱클릭에는 스크롤과의 구분 및 후속 click 억제가 필요하다. 확인 상태는 메뉴·제어권 수명에 묶고 서버에 저장하지 않는다. API/Android allowlist, 마지막 대상·스택·비활성 대상·포커스·실패·두 번 활성화·롱클릭 회귀 테스트와 모바일/실제 dev 화면을 검증한다. 생성 Remote 번들과 living doc을 갱신하고 별도 데이터 마이그레이션은 하지 않는다.
