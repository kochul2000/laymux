# 0390. 명시적 종료의 Codex 작업 취소는 대화 확인보다 먼저 수행한다

- Status: Proposed
- Date: 2026-11-25
- Source: 사용자가 종료 취소를 켜고도 장시간 Codex 리뷰 작업 때문에 닫을 수 없었던 보고, [ADR-0278](0278-codex-status-current-screen.md), [ADR-0314](0314-update-never-interrupts-terminals.md), [ADR-0366](0366-codex-close-proof-lives-through-fenced-save.md)
- 관계: 명시적 종료의 /status 확인 전에 허용하는 입력을 확장한다.

## Context

종료 확인은 활성 Codex 작업이 있는 화면을 거절한다. 터미널 작업 취소가 켜져 있어도 종료용 Ctrl+C는 복원점 저장 뒤에 실행돼 활성 Codex가 있는 경우 그 단계까지 도달하지 못한다. 사용자는 직접 앱을 닫을 때 장시간 리뷰 작업도 취소하고, 재기동 시 대화를 유휴 상태로 복원하기를 원한다.

## Decision

**명시적 종료를 확정했고 종료 시 작업 취소를 켰다면, 현재 입력창 위에 Codex가 표시한 작업 중단 안내를 확인해 Esc를 한 번 보낸다.** 이 입력은 Codex 프로세스를 유지한 채 작업을 취소한다. 창 닫기를 확정한 순간의 종료 설정은 backend 종료 예약과 frontend Ctrl+C 절차가 같은 값으로 사용한다. 승인과 전달은 기존 종료 토큰·대상 PTY generation·프로세스 재검증·입력 차단에 결부된다.

대상은 유휴 입력창을 확인한 뒤 기존 /status 절차를 진행한다. 취소 후 유휴 상태가 확인되지 않으면 원인을 보고해 기존 실패 처리로 반환한다. 검증된 복원점을 저장한 뒤 사용자 설정에 맞춰 모든 터미널의 종료용 Ctrl+C와 기록 캐시를 실행한다. 업데이트는 작업을 중단하지 않는다.

레이아웃과 대화 ID는 기존 방식으로 복원한다. 자동 리뷰 작업과 스킬 실행 상태는 복원 대상에 추가하지 않는다.

## Alternatives Considered

- Ctrl+C 전체 반복을 저장 전에 실행하면 Codex 자체가 종료돼 같은 대화의 ID를 직접 확인할 수 없다.
- 작업 중 표시를 무시하고 /status를 넣으면 쌓인 입력이 나중에 실행되거나 현재 작업의 입력으로 들어갈 수 있다.
- 리뷰어 pane만 식별하면 같은 화면에서 막히는 일반 Codex 작업의 종료를 해결하지 못한다.

## Consequences

일반 Codex 작업과 자동 리뷰의 취소가 같은 종료 확인 경로를 사용한다. 프로세스·세션 소유권과 기존 업데이트 보존 정책을 유지한다. 활동 화면과 백그라운드 요약, 창 닫기를 확정할 때의 취소 설정, 첨부 입력 차단, 타임아웃과 저장 순서를 검증한다.
