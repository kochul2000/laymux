# 0242. 스프레드시트는 Rust에서 읽고 데스크톱에서 값으로 표시한다

- Status: Proposed
- Date: 2026-09-08
- Source: 사용자 요청(셀 값·시트 전환·검색·복사), architecture/data-flow.md FileViewer, ADR-0109
- 관계: ADR-0109의 structured 렌더러를 바이너리 스프레드시트와 검색으로 확장한다.

## Context

파일 뷰어에서 xls, xlsx, xlsb, ods의 데이터를 확인해야 한다. 원본 서식, 차트, 편집,
수식 재계산은 필요하지 않다. Excel 실행 환경이나 웹 스프레드시트 엔진 동봉은 비용에 비해
필요한 기능이 적다. Remote는 별도 렌더러이며 이번 요청의 범위가 아니다.

## Decision

**calamine으로 파일을 읽고, 기존 데스크톱 FileViewer 안에서 React가 셀 값을 표시한다.**

- 네 확장자는 대소문자와 무관하게 인식한다. 기존 외부 뷰어 매핑이 우선한다.
- 데스크톱 전용 IPC `read_spreadsheet_for_viewer(path, sheet?)`가 시트 목록과 선택한
  시트의 셀 좌표·값을 반환한다. 기존 공유 `read_file_for_viewer` 및 Remote 계약은 유지한다.
- 파일 경로 해석은 기존 WSL/Windows 공통 경로를 사용한다. 파일 읽기와 파싱은 main thread 밖에서
  실행한다. 캐시·세션 상태·파일 쓰기는 만들지 않고 시트 전환마다 파일을 다시 읽는다.
- 셀 값은 HTML로 해석하지 않는다. 수식은 저장된 결과만 표시하며 재계산·매크로 실행을 하지 않는다.
- 원본은 16 MiB, ZIP 해제 데이터는 64 MiB로 제한한다. xlsx/xlsb는 sparse cell reader로
  읽어 먼 셀 하나 때문에 거대한 직사각형을 할당하지 않는다. ODS는 파싱 전에 통합 문서 전체
  반복 셀 영역을 1,000,000셀, 공백 반복·문자열×행/열 반복의 확장량을 64 MiB로 제한한다.
- 표시 데이터는 첫 10,000행·256열 안의 최대 100,000개 비어 있지 않은 셀, 값 총량 4 MiB로 제한한다.
  잘린 경우 경고를 표시하고 검색·복사가 로드된 범위에 한정됨을 명시한다.
- 검색은 현재 시트에서 일치하는 행을 필터링한다. 표는 페이지 단위로 렌더한다.
  복사는 셀 하나 또는 필터링한 전체 행을 TSV로 제공하며, 페이지 밖의 검색 결과도 포함한다.
- 오류는 인라인으로 알리고 기존 오버레이의 OS 열기를 유지한다. 암호화 파일은 지원하지 않는다.

## Alternatives Considered

- SheetJS와 완성형 웹 그리드: Rust의 파일 접근 경계와 별도로 바이너리를 프론트에 전송하고
  의존성을 추가할 이유가 없다. 기존 React 표로 요청 범위를 충족한다.
- 공유 FileViewerContent variant 확장: Remote까지 스키마·렌더러를 넓히므로 데스크톱 전용 IPC를 선택한다.
- 모든 셀을 한 번에 DOM으로 렌더: 큰 시트에서 UI가 멈추므로 페이지를 사용한다.
- 통합 문서 캐시: 반복 파싱은 줄지만 파일 변경·수명·동시 요청의 상태 관리가 생긴다.
  실제 시트 전환 지연이 문제가 되면 재검토한다.

## Consequences

플랫폼별 Excel 설치 없이 네 형식을 읽는다. Rust 의존성과 작은 표 UI가 추가된다.
원본 모양이나 최신 수식 결과를 보장하지 않는다. calamine의 legacy xls 파서는 시트 데이터를
먼저 메모리에 올리므로 원본 크기와 표시 상한만으로 파서 메모리가 그 크기에 제한되지는 않는다.
Remote는 기존 미지원 파일 표시·다운로드를 유지한다.
실제 네 형식 fixture, 손상·상한·시트 전환·검색·복사·늦은 응답 테스트와 dev 화면 검증을 수행한다.
더 큰 파일, 원본 서식 또는 Remote 표시가 필요하면 별도 범위로 결정한다.
