# 0378. 설정의 즉시 적용 작업은 저장 초안과 구분하고 프로필 삭제는 공통 확인 정책을 따른다

- Status: Proposed
- Date: 2026-11-09
- Source: 사용자 UI 개선 요구, [#1306](https://github.com/kochul2000/laymux/issues/1306), [api-contracts.md 설정 화면](../architecture/api-contracts.md), [ADR-0333](0333-destructive-confirmation-global-and-pane-control-bar.md)
- Extends: ADR-0333의 클릭 확인 적용 대상을 설정 프로필 삭제로 확장한다.

## Context

설정에는 저장 초안과 즉시 적용 작업이 공존한다. 언어 변경과 프로필 추가·삭제는 store를 바로 바꾸지만 하단에는 변경 사항 없음과 비활성 변경 취소가 표시된다. 사용자는 어떤 작업을 저장하거나 취소할 수 있는지 구별하기 어렵고 프로필 삭제도 첫 클릭에 실행된다. 기존 설정 소유권과 저장 방식을 유지하면서 적용 시점과 파괴적 작업의 의도를 명확히 해야 한다.

## Decision

**즉시 적용 작업은 동작 근처의 설명과 실행 결과로 저장 초안과 구분하고, 프로필 삭제는 기존 전역 클릭 확인 정책을 따른다.**

언어·프로필의 정본과 적용 경로는 기존 settings store로 유지한다. 즉시 적용은 저장·변경 취소가 처리하는 draft에 포함하지 않으며 그 범위를 화면에 명시한다. 실행 결과는 현재 SettingsView의 비영속 안내 상태이고 설정 값의 정본이 아니다. 프로필 삭제는 공용 TwoClickConfirmButton과 confirmDestructiveActions 값을 사용한다. 확인 상태는 버튼 로컬이며 blur·이탈·Escape에서 취소한다. 확인 시 대상 이름을 접근성 문구에 포함하고 버튼 글자도 바꾼다. 프로필 내용 편집과 다른 설정의 저장·영속·API 계약은 변경하지 않는다.

## Alternatives Considered

- 언어와 프로필 작업을 모두 draft로 전환하면 취소는 통일되지만 기존 즉시 언어 표시와 프로필 선택·참조 수명까지 바꿔야 하므로 이번 UI 수정 범위를 벗어난다.
- 일반 저장 안내만 추가하면 개별 작업의 적용 시점과 삭제 확인은 여전히 드러나지 않는다.
- 별도 native 확인창은 기존 공용 버튼과 입력·포커스 흐름이 달라지고 새 모달을 관리해야 하므로 사용하지 않는다.

## Consequences

사용자는 즉시 적용과 저장 대기 편집을 구분할 수 있고 기본 설정에서 프로필 삭제에 한 번의 확인이 추가된다. 확인을 끈 기존 사용자는 즉시 삭제 동작을 유지한다. 즉시 적용 작업 전체의 되돌리기를 제공하는 것은 아니므로 언어·프로필 안내와 회귀 검증이 필요하다. 저장 초안의 범위를 통합할 요구가 생기면 별도 결정으로 재검토한다.
