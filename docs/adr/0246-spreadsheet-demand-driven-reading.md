# 0246. 스프레드시트 셀 파싱은 스크롤 요청에 따라 진행한다

- Status: Accepted
- Date: 2026-09-08
- Source: 사용자 요청(스크롤 유지, 실제 구간 읽기), ADR-0242·0244
- 관계: ADR-0244의 선행 셀 읽기를 요청 기반으로 변경한다. 가상 렌더링·선택은 유지한다.

## Context

DOM 가상화는 화면 비용만 줄이며 셀을 먼저 모두 파싱하는 비용을 줄이지 않는다.
사용자는 PC 지연의 원인이 뷰어라고 단정하지 않되, 보지 않는 구간을 먼저 읽지 않기를 요구했다.
calamine의 XLSX/XLSB 셀 reader는 순차 진행을 지원하지만 XLS/ODS는 선행 파싱이 필요하다.
매 구간마다 파일을 다시 열면 앞부분을 반복 파싱하므로 사용하지 않는다.

## Decision

**파서와 파일의 소유권을 읽기 작업자에 두고, 다음 구간 요청마다 최대 100행을 진행한다.**

- Tauri가 관리하는 `SpreadsheetStreams`가 최대 4개 작업자의 요청 채널을 소유한다. AppState의 다른 락을 잡지 않는 독립 leaf lock이다. 락을 잡은 채 파싱·응답 대기하지 않는다.
- `open_spreadsheet_for_viewer(path,sheet?)`가 첫 구간과 sessionId를 반환하고 `next_spreadsheet_for_viewer(sessionId)`가 이어 읽는다. 응답은 `{sessionId,content,loadedRows,hasMore}`다. `content` 셀은 이번 구간만 포함한다.
- XLSX/XLSB 작업자는 calamine reader를 유지한다. 다음 행 확인에 필요한 셀 하나만 look-ahead한다. 구간 사이에는 채널에서 대기하고 셀 파싱하지 않는다.
- 원본 ZIP 읽기·안전 검사·공유 문자열 준비 비용은 열 때 발생한다. 압축 파일의 임의 위치 직접 읽기나 전체 비용의 상수 시간 보장은 하지 않는다.
- XLS/ODS는 부분 파싱을 보장하지 않으므로 원본 2 MiB까지만 허용한다. ODS는 압축 해제·반복 문자열 8 MiB, 반복 셀 영역 100,000셀까지로 제한한다. XLSX/XLSB의 원본 16 MiB·ZIP 64 MiB 상한은 유지한다.
- UI는 스크롤 하단 접근 시 다음 구간 하나만 요청한다. 읽은 데이터만 누적하며 기존 총 10,000행·256열·100,000셀·값 4 MiB 상한을 유지한다. 검색·복사는 읽은 범위에 한정된다고 표시한다.
- 파일/시트 변경·닫기에서 `close_spreadsheet_for_viewer(sessionId)`로 채널을 해제한다. 늦은 open 응답도 즉시 닫는다. 읽기 중 닫기는 현재의 제한된 구간 완료 후 작업자를 종료한다. 종료된 작업자는 다음 open 때 목록에서 제거한다.
- 열려 있는 reader는 열 때 읽은 파일 버전을 본다. 파일 변경을 반영하려면 다시 연다. 세션·파서는 디스크나 설정에 영속하지 않는다.
- 헤더를 가리는 스크롤 뷰포트에는 padding을 두지 않는다. 파일 뷰어의 본문 여백을 상속하면 sticky 헤더 위에 빈 띠가 생기므로 스프레드시트 표에서만 제거한다.

## Alternatives Considered

- Next UI로 회귀: 화면 탐색만 바꾸며 사용자도 원인 미확정과 스크롤 유지를 명시했다.
- 요청마다 재파싱: 세션은 없지만 스크롤할수록 앞부분 읽기가 반복된다.
- 모든 형식용 새 파서: XLS/ODS 부분 파서를 직접 구현하는 비용이 커서 작은 파일만 지원한다.

## Consequences

보지 않은 XLSX/XLSB 구간은 셀 파싱하지 않는다. 대신 제한된 작업자 수·채널·닫기 계약이 추가된다.
읽은 구간을 다시 볼 때 재파싱하지 않으며 누적 메모리는 기존 상한에 제한된다.
작업자 대기·다음 구간·닫기, 중복 스크롤·늦은 응답, 실제 dev 스크롤과 헤더 위치를 검증한다.
