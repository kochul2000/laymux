# 0285. 훅 명령은 읽을 수 있는 형태로 설치하고 변경 개수를 먼저 안내한다

- Status: Proposed
- Date: 2026-09-29
- Source: 사용자 요구(EncodedCommand 제거, 추가 훅 개수 안내, Settings 재구성), [ADR-0282](0282-optional-agent-hook-installation.md), [ADR-0284](0284-codex-title-hook-binding.md)
- 관계: ADR-0282의 선택 설치와 정확한 소유 명령 식별 원칙을 유지하며 실행 형식과 소유 명령의 알려진 이전 형식을 구체화한다.

## Context

Windows 훅이 Base64 EncodedCommand를 사용해 사용자가 CLI 신뢰 화면에서 실행 내용을 읽을 수 없다. 설정 화면도 감지 선택, 설치 대상, 긴 안내와 수신 진단을 같은 수준으로 노출하여 무엇을 설치하는지 파악하기 어렵다. 기존 배포의 훅을 재설치할 때 이전 명령을 남기면 이벤트가 중복 실행된다.

## Decision

**훅 실행 경로와 인자를 평문으로 등록하고, 기존 설치 관리 API의 이벤트 개수를 설치 버튼 옆에서 안내한다.**

- 이벤트 종류와 상태 전이는 유지한다. 명령의 인용은 실행 셸에 맞추고 공백·한글·따옴표·셸 특수문자 경로를 실제 프로세스 실행으로 검증한다. Windows Codex는 기본 cmd 실행 경계를 거치는 평문 PowerShell 명령, Windows Claude는 명시적 PowerShell 셸의 평문 명령, Linux/WSL은 POSIX 인용 명령을 사용한다.
- 신규 설치는 EncodedCommand를 생성하지 않는다. 재설치·제거는 현재 경로/provider로 생성한 정확한 신규 명령 또는 알려진 이전 EncodedCommand만 소유 항목으로 취급한다. 임의 명령의 디코딩·추정 매칭은 하지 않는다. 실행 의미를 바꾸는 shell·args·commandWindows 필드도 소유권 비교에 포함한다.
- 설치 수는 backend의 expected/registered 값에서 도출한다. 신규 설치는 N개 추가, 부분 설치는 전체 N개 중 누락 M개 추가, 재설치는 N개 갱신임을 명시한다. 기존 사용자 훅은 보존한다.
- Settings는 감지 방식과 환경별 설치를 시각적으로 분리한다. 설치 개수·설치 상태·버튼과 즉시 적용 안내는 항상 보이고, 사용자 지정 경로와 추가 진단은 상세 영역으로 제공한다. 감지 선택은 일반 저장, 설치·제거는 즉시 적용이라는 계약을 유지한다.

## Alternatives Considered

- EncodedCommand 유지와 설명만 추가: 실제 실행 내용을 CLI에서 읽을 수 없다는 문제를 해결하지 못한다.
- 모든 환경에 같은 인용 문자열 사용: cmd·PowerShell·POSIX 셸의 해석 차이로 경로나 실행 의미가 달라질 수 있다.
- 명령 변경 시 이전 훅을 사용자에게 직접 삭제하도록 요구: Laymux가 설치한 항목이 중복 실행될 수 있어 관리 기능의 책임을 충족하지 못한다.

## Consequences

사용자가 신뢰할 명령과 설치 범위를 확인할 수 있다. 셸별 인용과 이전 소유 명령 정리를 검증하는 비용이 남는다. 기존 설치에는 명시적 재설치가 필요하고 Codex가 변경된 명령의 신뢰 확인을 다시 요청할 수 있다. 상태 감지 기능·기본값·이벤트 집합·저장 스키마는 유지한다.
