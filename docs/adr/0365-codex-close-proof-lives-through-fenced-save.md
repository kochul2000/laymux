# 0365. Codex 종료 확인 결과는 입력 차단을 유지한 저장까지 유효하다

- Status: Proposed
- Date: 2026-10-31
- Source: 사용자 보고(`activeButUnidentified`로 종료 차단), dev 빈 대화의 `/status` 성공 후 26초 저장 지연 재현, [data-flow §13.5](../architecture/data-flow.md), [ADR-0270](0270-codex-status-checkpoint-probe.md), [ADR-0278](0278-codex-status-current-screen.md)
- 관계: ADR-0270의 확인 결과 만료 정책을 부분 대체한다. 업데이트 대상 정책(ADR-0323)은 유지한다.

## Context

공유 서버를 사용하는 Codex의 빈 새 대화는 rollout과 TUI lifecycle 로그가 없을 수 있다. 종료 직전 `/status`는 그 대화의 전체 ID와 기록 부재를 확인하여 Fresh로 저장할 수 있다. 그러나 기존 25초 토큰 기한에는 대상 탐색·입력·화면 판독뿐 아니라 최종 이중 관측·DB 저장·기록 저장까지 포함된다. 확인에 성공한 뒤 저장이 지연되면 입력은 계속 차단되어 있는데 확인 결과만 사라져 일반 귀속의 `activeButUnidentified`로 돌아간다. dev의 실제 WSL Codex에서 지연 없는 저장은 Fresh로 통과하고, 같은 대화의 확인 뒤 26초 지연은 사용자와 같은 오류로 실패했다.

ID나 파일 부재를 추측해 빈 대화로 처리하거나 미확인 대화 전체의 종료 검증을 생략해서는 안 된다. 늦게 도착한 입력을 차단하는 기한과, 이미 확보한 확인 결과를 저장하는 수명은 구분해야 한다.

## Decision

**기한 내 모든 Codex 확인을 마친 뒤 결과를 봉인하고, 같은 입력 차단과 토큰 아래 최종 저장·정리 완료까지 보존한다.**

- 확인 수집에는 기존 25초 기한을 적용한다. 전체 대상의 proof와 입력 절차 완료를 확인한 내부 IPC만 저장 단계로 전환한다. 기한 초과·부분 확인·차단 소유권 상실은 전환할 수 없다.
- 저장 단계에서는 수집 기한 경과만으로 proof를 버리지 않는다. 추가 상태 확인 입력과 화면 판독은 거절한다. 토큰·PTY generation·현재 프로세스와 incarnation·대화 변경·rollout 검증 및 critical 이중 관측은 유지한다. 화면 확인 결과에도 그때의 live 제목 snapshot을 결부하며, 제목의 변경·소실이나 다른 대화와의 충돌을 이전 proof로 덮지 않는다.
- 저장 단계 전환은 저장 성공이 아니다. DB·기록 저장 실패는 기존 실패 경로를 따르고, 정리는 실패 시 차단을 해제하며 성공 시 창 파괴까지 차단을 유지한다. 과거 토큰은 새 차단을 해제할 수 없다.
- 이 수명은 메모리의 명시적 종료 transaction에만 속한다. 일반 저장·재시작 후·다른 transaction에는 proof를 재사용하지 않는다. native와 WSL에 같은 정책을 적용한다. 영속 스키마·사용자 설정은 추가하지 않는다.

## Alternatives Considered

- 전체 기한만 증가: 조회와 저장이 여전히 같은 기한을 소비하여 부하에 따라 같은 실패를 반복한다.
- 실패 후 `/status` 자동 재실행: 초안을 다시 조작하고 같은 조회 비용을 반복한다. 유효한 결과와 차단을 이미 소유하므로 불필요하다.
- rollout 없는 제목을 Fresh로 간주하거나 미식별 귀속의 종료를 허용: 삭제·손상·다른 대화와 빈 새 대화를 구별하지 못하여 기각한다.

## Consequences

확인에 성공한 빈 대화는 저장 지연 때문에 종료를 막지 않는다. 수집·저장 단계 전환과 정리 책임이 추가되며, 저장 정체 중에는 기존처럼 입력 차단을 유지하고 진행 상태를 표시한다. acquisition 만료, 부분 확인, 봉인 뒤 늦은 입력·화면, 프로세스·generation·대화 변경, 저장 실패의 차단 해제를 회귀 검사한다. dev에서 실제 native·WSL Codex의 빈 대화와 지연 저장을 확인한다. Codex가 공식 현재 대화 조회를 제공하면 입력 기반 확인 자체를 재검토한다.
