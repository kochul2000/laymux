# #1076 에이전트·MCP·휴대폰 연결 설정 계획

- 상태: 에이전트 연결 항목 구현 및 dev 검증 완료, PR 리뷰 대상. MCP·휴대폰 연결은 후속 범위다.
- 수정일: 2026-09-25
- 대상: [#1076](https://github.com/kochul2000/laymux/issues/1076). 이번 사용자 결정으로 기존 실습형 범위를 아래 세 가지 설정으로 대체한다.
- 선행: [#1078](https://github.com/kochul2000/laymux/pull/1078), [ADR-0265](adr/0265-pc-remote-first-use-defaults.md)
- 후속: [#1077 기본 활성 기능의 유지·설정·끄기 문맥 안내](https://github.com/kochul2000/laymux/issues/1077)
- 현재 구현 ADR: [0266 — 에이전트 연결 설정](adr/0266-agent-connection-setup.md). 이번 PR에서는 실제 에이전트 항목만 노출한다.

현재 구현의 자동 검사·실행은 Windows PowerShell·WSL을 지원한다. CMD·네이티브 Linux Bash와 해석 불가능한 래퍼에는 공식 문서와 새 수동 터미널을 제공한다. 기존 PTY의 시작 명령 지원 범위를 별도 검토하기 전에는 설치·실행 성공으로 표시하지 않는다. 아래 MCP·휴대폰 및 항목 간 전달은 후속 구현 계획이다.

## 1. 제품 형태

개발자가 필요한 연결을 빠르게 끝낼 수 있는 **연결 설정 페이지 하나**를 만든다. 항목은 에이전트 연결, MCP 연결, 휴대폰 연결의 세 개로 한정한다. 안내문·현재 상태·바로 실행할 설정 동작을 같은 위치에 둔다.

페이지 안에는 세 항목의 상태가 보이는 목록과 선택한 항목의 설정 본문을 둔다. 처음 열면 에이전트 연결을 먼저 보여준다. 에이전트를 준비한 다음 MCP 연결로 이어가도록 제안하며, 휴대폰 연결은 별도로 바로 선택할 수 있다. 순서를 강제하거나 나머지 항목을 잠그지 않는다.

앱은 현재 승인된 작업 화면으로 바로 열린다. 상단의 글자 있는 `연결 설정` 진입점과 설정 내부 링크에서 페이지를 선택적으로 연다. 설정의 기존 내비게이션·컨테이너를 재사용하고 최초 실행에 자동 표시하지 않는다. 닫으면 작업 화면으로 돌아가며, 다시 열면 검사 버튼으로 실제 준비 상태를 확인한다.

필수 실습, 연습 워크스페이스, pane 분할 과제, Composer·위젯 교육, 플로팅 조작 과제, 학습 진행률과 배지는 범위에서 제외한다.

## 2. 에이전트 연결 — 가장 먼저 완성할 항목

사용자가 막히는 설치·실행 환경·로그인·실행 명령을 한 흐름으로 정리한다.

| 순서 | 표시와 동작 |
|---|---|
| 사용할 에이전트 선택 | 현재 지원하는 에이전트 목록을 제공한다. 설치되어 있거나 이미 설정된 항목은 그 사실을 함께 표시한다. 선택만으로 전역 기본 에이전트를 바꾸지 않는다. |
| 실행 환경 확인 | 선택한 터미널 프로필을 기준으로 Windows 또는 WSL 배포판 등 실제 실행 위치를 보여준다. 설치 검사와 실행 명령이 같은 환경을 가리키게 한다. |
| 설치 확인 | 실행 파일·버전을 확인한다. 준비돼 있으면 설치 설명을 접고, 없으면 그 환경에 맞는 설치 방법과 명령 복사·터미널 열기·다시 확인을 제공한다. |
| 로그인 안내 | 에이전트가 제공하는 로그인 절차로 연결한다. 기존 자격 증명을 재사용하고 로그인 상태를 확인할 수 없는 경우에는 정확히 `확인 필요`로 표시한다. |
| laymux에서 실행 | 기존 에이전트 명령·프로필 설정을 보여주고 필요한 항목만 수정한다. 경로·인수 같은 세부 내용은 펼쳐 볼 수 있다. 사용자가 실행 버튼을 눌러 선택한 환경에서 에이전트를 연다. |
| 다음 연결 | 실행까지 준비됐으면 같은 에이전트·실행 환경을 MCP 설정 화면에 전달한다. 이어서 MCP를 설정하거나 바로 작업으로 돌아간다. |

실행 파일 검사 성공, 프로세스 시작, 로그인 확인은 서로 다른 상태다. PTY 생성만 성공했거나 터미널이 열렸다는 이유로 모두 준비됐다고 표시하지 않는다. 상태를 자동으로 알 수 없는 에이전트에는 해당 CLI에서 확인할 짧은 경로를 제공한다. 예제 과제를 완료하거나 유료 요청을 보내야 설정을 끝내는 구조는 만들지 않는다.

설치·로그인 명령과 검사 방법은 구현 시 각 에이전트의 공식 문서 및 실제 CLI 동작으로 확인한다. Windows와 WSL의 설치 위치를 섞어 안내하지 않는다.

## 3. MCP 연결

앞에서 고른 에이전트와 실행 환경을 이어받되 사용자가 바꿀 수 있게 한다. 페이지 처음에는 **에이전트가 laymux의 터미널 출력·화면 배치·파일 뷰어·설정을 도구로 다룰 수 있게 한다**는 목적과 대표 범위만 짧게 설명한다.

본문은 대상 에이전트/환경 확인 → laymux 서버 주소 확인 → 해당 클라이언트에 등록 → 연결 상태 확인으로 구성한다. 기존 등록이 있으면 먼저 보여주고, 현재 설정에서 필요한 항목만 적용한다. 복사·등록·다시 확인·오류 상세 보기를 가까이 둔다.

서버 응답, 클라이언트 등록 설정, 에이전트에서 사용 가능한 연결은 구분해 표시한다. health 응답만으로 에이전트 연결까지 정상이라고 하지 않는다. 자동 검증이 가능한 범위는 확인하고, 클라이언트 내부 확인이 필요하면 그 위치를 안내한다. 실제 pane 분할이나 MCP 과제를 필수 완료 조건으로 두지 않는다.

현재 `scripts/setup-mcp.sh/.ps1`는 Claude 등록용이다. 다른 에이전트에도 그대로 적용하지 않고 클라이언트별 지원 방식을 확인한다. 사용자 정의 등록을 통째로 덮어쓰지 않으며, 앱에서 실제 사용 중인 주소와 포트를 기준으로 안내한다.

## 4. 휴대폰 연결

기존 Remote 연결 화면을 재사용해 **접속 준비 → 휴대폰에서 열기 → 연결 확인**에 집중한다.

- 현재 연결 방식·실제 접속 주소·호스트의 준비 상태를 보여준다.
- 지원되는 방식의 연결 링크·QR 또는 앱 연결 안내를 제공한다. 브라우저 접속과 앱 전용 연결 방식을 같은 것으로 안내하지 않는다.
- 실제 연결 여부와 제어권 상태를 표시하고, 실패하면 주소·허용 범위·연결 오류에서 필요한 부분을 확인할 수 있게 한다.
- 연결 뒤에는 PC로 제어권을 가져오는 위치와 Remote 설정 진입점만 짧게 알려준다.

Composer 전송이나 플로팅 사용·이동을 연결 완료 조건으로 요구하지 않는다. 휴대폰 내부 학습 진행을 PC에 동기화하는 기능도 만들지 않는다. 연결 설정은 기존 인증·allowlist·제어권 정책을 그대로 사용한다.

## 5. 상태와 기존 설정 재사용

- 설치·서버 응답·현재 연결은 실제 조회 결과에서 계산한다. 별도의 학습 완료 상태나 단계 진행 엔진을 저장하지 않는다.
- 페이지에서 현재 선택한 항목은 일반 UI 상태로 관리한다. 실제 에이전트 명령·프로필·MCP 등록·Remote 연결 정책은 각 기존 설정의 소유권을 유지한다.
- 이전 연결 확인 결과와 지금 연결된 상태를 혼동하지 않는다. 다시 확인 중, 설정 변경 후 재확인 필요, 확인 불가, 실제 오류를 구분한다.
- 기존 설정 화면을 하나 더 복제하지 않는다. 핵심 준비 항목은 같은 편집 동작을 재사용하고, 고급 항목은 기존 설정의 정확한 위치로 연결한다.
- 자동으로 확인할 수 없는 상태를 감추기 위해 광범위한 사용 이력 수집이나 도구 호출 추적 체계를 만들지 않는다.
- #1077의 안내 숨김·유지·기능 끄기 상태는 별도다. 이번 페이지에서 기능을 켜거나 연결하는 명시적 설정 동작과 팁 확인 상태를 섞지 않는다.

## 6. 구현 순서와 코드 연결점

1. **설계 확정:** 페이지 배치, 검사 결과 모델, 대상 실행 환경, 등록 설정의 소유권, 필요한 진단 API를 새 Proposed ADR에 기록한다. 번호는 구현 시 최신 main에서 정한다. 이번 계획은 기존 ADR-0265를 변경하지 않는다.
2. **에이전트부터:** 페이지 틀과 에이전트 설정을 먼저 완성한다. 이미 설치된 환경, 미설치 환경, Windows/WSL 위치 불일치, 로그인 확인 불가, 실행 실패까지 이 항목에서 다룬다.
3. **MCP:** 선택한 에이전트/환경을 이어받아 등록·연결 확인·오류 해결 흐름을 붙인다.
4. **휴대폰:** 기존 Remote 설정·연결 UI와 상태를 연결해 세 번째 항목을 완성한다.
5. **통합 검증:** 세 항목의 기존 설정 보존과 재진입을 확인하고, #1076 완료 조건을 이번 범위에 맞춘다. 그 뒤 #1077의 문맥 안내를 진행한다.

재사용 후보는 `GridEditToolbar.tsx`의 진입점, `SettingsNavigation.tsx`와 `ui-store.ts`의 설정 이동, `SettingsView.tsx`의 에이전트 명령 설정, `agent-command.ts`의 파싱, 기존 프로필/WSL 환경 해석, `RemoteAccessModal.tsx`다. 실제 소유 모듈과 진단 API 경계는 ADR에서 확인한다.

코딩은 미디엄급 서브에이전트에 맡긴다. 에이전트 설정의 공통 기반을 먼저 고정한 뒤 나머지 항목을 분담한다.

- 관련 `docs/architecture/overview.md`, `data-flow.md`, `api-contracts.md`를 구현 PR에서 동기화한다.
